# 10 · Тестирование

Особенность проекта: **самое важное невозможно проверить автоматически.** «Трафик
идёт через туннель и не течёт мимо» требует реального устройства, реальной сети и
реального сервера. Поэтому стратегия двухчастная: автотесты покрывают всё, что
можно, а критичное закрывается дисциплинированным ручным чек-листом.

---

## Пирамида

```
        ручные сценарии          редко, перед релизом, на железе
      ────────────────────

────────────────────────────
```

## Юнит-тесты · основная масса

### Парсеры — самое ценное покрытие

Парсеры импорта ломаются чаще всего, потому что вход приходит из внешнего мира.
Держим **корпус реальных примеров**:

```
packages/commy_config/test/fixtures/
├─ links/          по файлу на схему, включая пограничные варианты
├─ subscriptions/  реальные ответы панелей: plain, base64, clash yaml, sing-box json
├─ headers/        варианты subscription-userinfo, включая неполные
└─ malformed/      битое: обрезанный base64, кривой JSON, чужой формат,
                   пустой ответ, HTML-страница ошибки вместо конфига
```

Правила корпуса:

1. **Каждый баг парсера добавляет фикстуру.** Регрессия ловится один раз.
2. Фикстуры **анонимизированы**: домены заменены на `example.com`, креды на
   синтетические. Реальные подписки в репозиторий не попадают.
3. Битые входы проверяются на то, что они дают `ImportFailure` с внятной причиной,
   а **не** на то, что они бросают исключение.
4. Частичный успех проверяется явно: 40 из 50 узлов импортированы, 10 в отказах.

### Генератор конфига

Детерминированность — обязательный инвариант, иначе golden-тесты невозможны.

- Одинаковый вход → байт-в-байт одинаковый JSON.
- Golden-файлы конфига на типовые комбинации: одиночный узел, узел + правила,
  все режимы маршрутизации, DNS-варианты.
- **Отдельный тест-инвариант:** в сгенерированном конфиге никогда нет `clash_api`
  для мобильных платформ.
- **Отдельный тест-инвариант:** собственный трафик приложения исключён из туннеля.

### Редакция логов

Набор строк с кредами прогоняется через редактор, проверяется отсутствие **каждого**
секрета в выводе. Новый тип секрета — новая строка в тесте. Это правило R3 в виде
кода.

### Домен

Use-case'ы против `FakeCoreClient` и фейковых репозиториев. Проверяются переходы
состояний туннеля, обработка отказов, что `Result` не теряет ошибку.

## Golden-тесты · дизайн-система

Каждый виджет `commy_ui` — в **обеих темах**. Это единственный способ не дать
светлой теме тихо сгнить.

- Фиксированная версия Flutter (FVM) — иначе golden'ы плывут от смены рендерера.
- Фиксированные шрифты (вшиты в приложение) — иначе плывут от системных.
- Состояния тоже покрываются: `ConnectButton` — шесть скриншотов на тему.
- Обновление golden'ов — **отдельный коммит** в PR, чтобы ревьюер видел, что
  изменилось визуально, а не искал это в диффе кода.

## Интеграционные тесты

### Контракт `CoreClient`

Один набор тестов, прогоняемый против **каждой** реализации. Это то, что не даёт
пяти платформам разъехаться:

- `start` → статус доходит до `connected`;
- `stop` → статус доходит до `idle`;
- ошибка ядра → статус `error` с причиной, а не зависание;
- поток трафика отдаёт значения;
- `urlTest` возвращает задержку или честный `null`;
- двойной `start` не создаёт два туннеля;
- `stop` без `start` не падает.

### Миграции БД

На каждую миграцию — тест, открывающий БД предыдущей версии и проверяющий, что
данные пережили переезд. Пользователь, потерявший профили после обновления, —
потерянный пользователь.

## Ручные сценарии · перед каждым релизом

Автоматизировать нельзя. Прогоняются на реальных устройствах и записываются в
чек-лист релиза.

### Обязательные

| # | Сценарий | Критерий |
|---|---|---|
| 1 | Первый запуск: импорт ссылки → подключение | Меньше 60 секунд |
| 2 | Импорт подписки на 100+ узлов | UI не виснет, квота показана |
| 3 | Замер всех узлов | Прогресс идёт, отмена работает |
| 4 | **Переключение Wi-Fi ↔ мобильная сеть** | Туннель жив, соединения не порваны |
| 5 | **Сон устройства 30+ минут** | Туннель жив после пробуждения |
| 6 | Смена узла на лету | Соединения не рвутся |
| 7 | Обрыв сети целиком → восстановление | Автопереподключение или понятная ошибка |
| 8 | Отказ в системном диалоге VPN | Понятная ошибка, не тупик |
| 9 | Убийство ядра извне | Статус `error`, kill switch сработал |
| 10 | **Полный [чек-лист утечек](09-security-privacy.md#чек-лист-утечек)** | Все пункты |

### Платформенные

| Платформа | Дополнительно |
|---|---|
| Android | Always-on VPN + block without VPN · Doze · раздельное туннелирование · перезагрузка с автозапуском |
| iOS | **Сутки непрерывной работы без jetsam** · on-demand по SSID · большие наборы правил в пределах 50 MiB |
| Windows | Установка службы · портативный режим · закрытие окна не рвёт туннель · перезагрузка |
| macOS | Регистрация хелпера · Gatekeeper на чистой машине · menu bar |
| Linux | **Восстановление DNS после краша приложения** · три среды DNS · работа без трея · Wayland и X11 |

Пункты, выделенные жирным, — те, что чаще всего ломаются и дороже всего обходятся
пользователю.

## Устройства

Минимальный парк для осмысленного тестирования:

| | Зачем |
|---|---|
| Android 8–9, слабое устройство | Нижняя граница поддержки, Doze, память |
| Android 14+ | Новые требования к foreground-сервисам |
| iPhone на актуальной iOS | Лимит памяти расширения |
| iPhone постарше | Тот же лимит на меньшей памяти |
| Windows 10 и 11 | Служба, SmartScreen |
| macOS актуальный | Нотаризация, хелпер |
| Ubuntu + Fedora | systemd-resolved и NetworkManager |

Эмуляторы годятся для UI и не годятся для туннеля.

## Что НЕ тестируем

Осознанно, чтобы не тратить время впустую:

- **Само ядро sing-box.** Это ответственность апстрима. Мы тестируем свою обёртку.
- **Реализации протоколов.** См. выше.
- **Скорость соединения.** Зависит от сервера и сети, не от нас.
- **UI на всех разрешениях подряд.** Три точки перелома + системный шрифт 200%.

## Метрики покрытия

Число покрытия само по себе бессмысленно. Смотрим на то, где покрытие обязано быть
высоким:

| Пакет | Требование |
|---|---|
| `commy_config` | Максимальное. Здесь ломается чаще всего |
| `commy_domain` | Высокое. Чистая логика, тестируется дёшево |
| `commy_core` | Контракт покрыт для каждой реализации |
| `commy_ui` | Golden'ы важнее процентов |
| `commy_data` | Миграции покрыты обязательно |
| `apps/commy` | Низкое приемлемо — это склейка |
