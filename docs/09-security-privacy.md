# 09 · Безопасность и приватность

Commy — приложение, через которое идёт **весь трафик пользователя**. Ошибка здесь
дороже любой другой ошибки в проекте. Этот документ — не формальность.

---

## Модель угроз

Против кого защищаемся и чем.

| Противник | Что может | Наша защита |
|---|---|---|
| **Пассивный наблюдатель сети** | Видит метаданные соединений | Задача ядра, не наша. Наша задача — не создать утечку мимо туннеля |
| **Вредоносная подписка** | Подсовывает конфиг, уводящий трафик или ломающий парсер | Валидация всего входа, генерация конфига **нами**, а не пропуск чужого JSON в ядро как есть |
| **Другое приложение на устройстве** | Читает нашу БД, слушает управляющий сокет | Шифрование БД, secure storage, токен на управляющий канал, права на файлы |
| **Тот, у кого в руках разблокированное устройство** | Открывает приложение, видит серверы | Вне модели. Блокировка по биометрии — post-1.0 и всё равно не спасёт от полного доступа |
| **Мы сами** | Случайно логируем креды, случайно шлём запрос наружу | Правила R1/R3, редакция логов, чек-листы ниже |
| **Форк или пересборка** | Добавляет телеметрию под нашим именем | GPL и воспроизводимые сборки: пользователь может проверить, что APK собран из этого кода |

**Вне модели угроз:** компрометация самого устройства (root, malware с системными
правами), атаки на сервер пользователя, деанонимизация по поведению трафика.
Мы не обещаем анонимность — мы обещаем, что не мешаем и не подглядываем.

## Тишина в сети · правило R1 и его исключения

Базовое правило: **приложение не делает исходящих запросов, которых пользователь не
запросил.** Ни аналитики, ни crash-репортов, ни «проверки лицензии».

Из этого правила есть ровно **три** узаконенных исключения. Каждое разрешено явным
решением владельца проекта. Список закрытый: четвёртое исключение добавляется
только через новое решение и запись здесь.

| # | Исключение | Когда срабатывает | Ограничения |
|---|---|---|---|
| **E-1** | Проверка внешнего IP и страны | **Только по нажатию кнопки** пользователем | Endpoint настраивается, по умолчанию поле пустое или указан общеизвестный сервис. Запрос идёт **через туннель** — иначе он бессмыслен. Результат не сохраняется |
| **E-2** | Загрузка наборов geoip и geosite | **Только по явному действию** (кнопка «Загрузить правила») | Источник настраивается пользователем, включая своё зеркало. Файлы кешируются с версией. Автообновление — только если пользователь его включил |
| **E-3** | Списки блокировки рекламы | **Только если функция включена** пользователем | Источник настраивается. Обновление по интервалу, который задаёт пользователь. Выключено по умолчанию |

Общие требования ко всем трём:

- пользователь **видит**, куда пойдёт запрос, до того как он уйдёт;
- в настройках есть один экран, где перечислены все три с их адресами и статусом;
- ни один из них не является условием работы приложения — выключив все, пользователь
  получает полностью рабочий клиент;
- запросы не содержат идентификаторов устройства, установки или пользователя.

#### E-3 сегодня: тот же файл, что и E-2

Блокировщик — это правило по списку `geosite-category-ads-all`, а список лежит
там же, где наборы E-2, качается той же кнопкой и с того же настраиваемого
адреса. Отсюда три следствия:

- **таймера нет.** E-3 разрешает обновление по интервалу, который задаёт
  пользователь; реализована только загрузка по нажатию. Это уже разрешённого,
  а не шире;
- **выключенный переключатель не скачивает ничего** и ничего не просит: список
  появляется в «Наборах правил» только после того, как функцию включили;
- **включённый переключатель без списка ничего не блокирует** — и говорит об
  этом строкой под собой, а не молча.

Само блокирование делается в двух местах сразу: DNS-запрос к рекламному имени
получает отказ (`action: reject` — REFUSED, `dns/router.go` в v1.13.16), а
соединение с таким адресом отклоняется в маршрутизации. Первое — потому что
«блокировщик через DNS» означает именно это; второе — потому что имя может
прийти из системного кеша или не спрашиваться вовсе.

### Проверка обновлений — сознательно НЕ реализуем

Владелец проекта решил не добавлять проверку новых версий.

**Принятый риск:** пользователь, установивший APK напрямую или портативную сборку
Windows, **не узнает о критическом исправлении безопасности**. Google Play, F-Droid
и App Store обновят своих пользователей сами; остальные — нет.

Компенсация: в `README` и на экране «О программе» — заметная ссылка на страницу
релизов и рекомендация подписаться на уведомления GitHub. Это слабее автопроверки,
но это осознанный выбор в пользу принципа.

### HWID при запросе подписки — не исключение, но идентификатор

**Решение владельца, 2026-09-18** («как Happ / INCY»). Запрос подписки несёт
заголовки `x-hwid`, `x-device-os`, `x-ver-os` и `x-device-model`. Подробный
разбор решений — [ADR-0009](adr/0009-device-identifier.md).

Это **не четвёртое исключение из R1**: правило — про хосты, а заголовки уходят
туда же, куда запрос уходил и раньше, — на хост подписки, который ввёл
пользователь. Ни E-1, ни E-2, ни E-3 их не получают; требование «запросы не
содержат идентификаторов» для этих трёх остаётся в силе буквально.

Но это идентификатор, и он описан здесь, потому что обещание «нет телеметрии»
остаётся правдой, только если сказано всё:

| Вопрос | Ответ |
|---|---|
| Что это | Случайный UUID v4 **установки**. Не `ANDROID_ID`, не серийный номер, не MAC. Создаётся при первом запросе подписки, а не при установке |
| Кому уходит | Только хосту подписки. Панели он нужен как ключ счётчика устройств |
| Зачем | Панели с лимитом устройств (Remnawave) клиенту без `x-hwid` отдают заглушку «App not supported» вместо серверов |
| Как выключить | Настройки → «Идентификатор устройства». Выключено — не отправляется **ничего** из этой группы, и идентификатор даже не создаётся |
| Как сменить | Там же, «Сбросить идентификатор»; переустановка делает то же самое |
| Где лежит | Secure storage (`commy.device.id`), в открытую БД не пишется |
| В логах | Вырезается: это UUID, а редактор вырезает любой UUID (R3); закреплено тестом |
| Почему один на установку, а не на хост | У провайдера бывает несколько зеркал одной панели. Идентификатор «на хост» приватнее, но то же устройство при смене домена считалось бы новым и съедало лимит |

Версия ОС и модель устройства приходят **методом канала** `deviceInfo`, а не
из новой зависимости, и секретами не считаются: это те же строки, которые
устройство отдаёт каждому сайту в User-Agent. Поле, на которое платформа не
ответила, не отправляется — заголовок с догадкой хуже отсутствующего, потому
что панель его сохранит и покажет пользователю как имя его устройства.

По умолчанию **включено** — решение владельца: пользователь, импортировавший
подписку и получивший «App not supported», не может догадаться, в чём дело.

**И обратная сторона: заглушка панели — это сообщение, а не сервер.** Панель,
которая отказалась обслуживать клиента, присылает одну строку с адресом
`0.0.0.0` и причиной там, где у сервера имя. Приложение не показывает её
сервером: строка не попадает в список, в группу «Авто» и в сгенерированный
документ, а её текст стоит в карточке подписки — словами панели и без
перевода. Проверяется **адрес**, а не имя: имя — свободный текст на языке
администратора. Правило — `PanelNotice` в `commy_domain`.

## Секреты

### Где что лежит

| Данные | Где | Почему |
|---|---|---|
| URL подписок (содержат токен) | secure storage | Токен = доступ ко всем серверам пользователя |
| UUID, пароли, приватные ключи, Reality short-id | secure storage | Креды доступа |
| Ключ шифрования БД | secure storage | |
| Идентификатор установки (HWID) | secure storage | Единственное значение, которое связывает между собой все запросы подписок одной установки |
| Токен управляющего канала (десктоп) | Файл с правами только для текущего пользователя | |
| Всё остальное (имена, задержки, правила, статистика) | Зашифрованная SQLite | Дёшево зашифровать всё, чем каждый раз решать, что чувствительно |
| Сгенерированный конфиг ядра | Зашифрованная БД или память | **Содержит все креды в открытом виде** |

Бэкенды secure storage: Keychain (Apple), Keystore / EncryptedSharedPreferences
(Android), DPAPI (Windows), libsecret (Linux).

### Известная слабость: Linux без keyring

Если в системе нет `libsecret`, безопасного хранилища просто нет. В этом случае
приложение обязано:

1. **сказать об этом прямым текстом** при первом запуске;
2. предложить выбор: файл с правами `0600` или ввод пароля при каждом старте;
3. показывать индикатор пониженной защиты в настройках.

Молчаливая деградация до файла — это баг, а не «graceful fallback».

## Редакция логов · правило R3

Логи ядра содержат домены, IP, SNI и иногда куски конфигурации. Их копируют в чаты
и приклеивают к issue на GitHub. Значит, редакция обязательна.

### Что вырезается всегда

| Что | Замена |
|---|---|
| UUID, пароли, приватные ключи, `short_id`, `extra` XHTTP-узла | `[redacted]` |
| Токены и query-параметры в URL подписок | `https://panel.example.com/[redacted]` |
| `Authorization` и подобные заголовки | `[redacted]` |
| IP-адрес и порт сервера пользователя | `[server]` при экспорте, видно в живом просмотре |

### Что остаётся

Уровень, время, компонент, тип события, текст ошибки, SNI и домен назначения.
Без них лог бесполезен для отладки, а именно ради отладки его и экспортируют.

### Как реализовано

Редакция — **на слое вывода**, а не на слое записи. Живой просмотр в приложении
показывает больше, экспорт и копирование — меньше. Экспортировать сырой лог можно,
но только через явное подтверждение с текстом о том, что именно в нём окажется.

Тест обязателен: набор строк с кредами прогоняется через редактор и проверяется на
отсутствие каждого секрета. Добавили новый тип секрета — добавили строку в тест.

## Чек-лист утечек

**Обязателен к прохождению при любом изменении туннеля, маршрутизации или DNS
(правило R6).** Прогоняется на реальном устройстве, а не в тестах.

> **Прогон 2026-09-21 (сессия 11), эмулятор `commy_api36` + живой VLESS-сервер
> на машине разработчика.** Отмечено то, что эмулятор может ответить честно;
> остальное ждёт телефона и названо ниже своим именем. Как поднять узел за пять
> минут — docs/17, «Сессия 11».
>
> | Пункт | Чем проверено |
> |---|---|
> | Системный резолвер не используется в обход туннеля | DNS поднятого VPN — `172.19.0.2` (адрес TUN), не `10.0.2.3`. Запросы перехватываются (`match[1] protocol=dns => hijack-dns`) и уходят на `1.1.1.1:853` **через прокси** — видно в логе сервера |
> | После отключения системный DNS восстановлен | `DnsAddresses: [/10.0.2.3]` на `wlan0` сразу после отключения; резолв работает и отвечает **другим** адресом, чем через туннель |
> | IPv6 не остаётся «мимо» | У этого образа есть IPv6-дефолт (`::/0 -> fe80::2 wlan0`), так что проверка не пустая: с поднятым туннелем `default dev tun0` стоит и в IPv4-, и в IPv6-таблице `1019` |
> | Приложение исключено из собственного туннеля | В правилах маршрутизации диапазоны uid `0–10215`, `10218–20215`, `20218–…` — дыра ровно на два наших пакета. Обновление подписки при поднятом туннеле дало **ноль** соединений на сервере |
> | Локальные адреса ходят напрямую | Соединение с туннелированного uid на `10.0.2.2:18080`: `inbound/tun` → `outbound/direct[direct]`, панель его получила |
>
> **Не проверено, нужен телефон или настоящая сеть:** kill switch при падении
> ядра; переход Wi-Fi ↔ мобильная сеть; выход из сна; перезагрузка с
> автозапуском; FakeIP и системный кеш (FakeIP выключен по умолчанию);
> обход через явную привязку к интерфейсу при `strict_route` (нужен root);
> адресаты E-1/E-2/E-3 (исключения выключены по умолчанию).

> **Прогон 2026-09-23 (сессия 15), эмулятор `commy_lite` (API 36, образ
> google_apis, рутованный) + стенд `scripts/emulator_stand.sh`: девять живых
> узлов (REALITY Vision/gRPC/XHTTP, TLS‑XHTTP, Trojan, SS2022, VMess‑WS,
> Hysteria2, TUIC) и панель с лимитом HWID на этой же машине.** Датчики — не
> экран: `tcpdump` внутри гостя (что реально ушло с `wlan0`), счётчики
> `iptables -m owner` по UID (кто пытался), зонд `probe loop` (когда трафик
> остановился и когда пошёл), журнал доступа Xray (что прошло через узел). Как
> повторить — docs/18-emulator-testing.md.
>
> | Пункт | Результат |
> |---|---|
> | Смена сети не роняет трафик наружу | Wi‑Fi выключен на 12 с и включён: `tun0` тот же (не пересоздан), с UID обычных приложений на `wlan0` — ноль пакетов; трафик пошёл сам через ~0,2 с после того, как новая сеть стала сетью по умолчанию. Мимо туннеля — только собственные пробы Android (`network_stack`, uid 1073: connectivitycheck) и DHCP, это платформа, а не приложения |
> | Wi‑Fi ↔ мобильная сеть, настоящий переход | Эмулятор Android 11 (`aosp_atd`, в нём есть и Wi‑Fi, и LTE): Wi‑Fi → LTE → Wi‑Fi при непрерывной нагрузке через REALITY Vision и через Trojan — `tun0` тот же, потерян **один** запрос, бывший в полёте в момент переключения (70 из 71, 66 из 67), от приложений на `wlan0` и `eth0` — ноль пакетов, всё к цели шло через `tun0` |
> | Выход из сна не оставляет окна | Экран выключен + `deviceidle force-idle` (глубокий Doze) на 40 с и пробуждение: 75 запросов из 75 прошли, 4 МиБ скачались посреди Doze, мимо туннеля — ноль |
> | Падение ядра, kill switch выключен: пользователь **видит** разрыв | Был дефект: процесс с ядром убит (`kill -9`) — VPN снят, трафик пошёл напрямую, как и должен без kill switch, **а уведомление продолжало показывать «Подключено»**. Исправлено (сессия 15): уведомление снимается, приложение открывается на «Ядро аварийно завершилось» |
> | Падение ядра, kill switch включён: трафик **блокируется** | «Постоянный VPN» + «Блокировать соединения без VPN»: после `kill -9` приложения получают `connect: permission denied`, на `wlan0` от них ничего; обновление подписки при этом работает (приложение‑VPN системой исключено из блокировки) |
> | Перезагрузка с автозапуском | С системным kill switch — окна нет: до подключения приложения заблокированы, уведомление «Commy не подключён» одним тапом открывает приложение и подключает (было: открывало и не подключало — исправлено). Без kill switch окно есть **по замыслу**: конфиг с секретами нельзя поднять без приложения (R2), и уведомление говорит об этом сразу после загрузки |
> | Явная привязка к интерфейсу при поднятом туннеле | `ping -I wlan0` от shell (uid 2000) и от UID приложения: пакеты считаются в `OUTPUT`, но `tcpdump` на `wlan0` пуст — наружу не уходит ничего |
> | Запросы E‑1 идут туда, куда заявлено | Проверка IP ушла на `ipinfo.io:443` **через выбранный узел** (журнал Xray), ответ — адрес выхода. Адрес хоста теперь виден в настройках до запроса |
>
> **Не проверено:** FakeIP и системный кеш; адресаты E‑2 и E‑3; настоящий
> телефон.

### DNS

- [ ] DNS-запросы не уходят мимо политики — проверено перехватом на роутере или
      сторонним сервисом проверки утечек
- [ ] Системный резолвер не используется в обход туннеля
- [ ] При включённом FakeIP реальные адреса не утекают в системный кеш
- [ ] После отключения туннеля системный DNS **восстановлен** (особенно Linux)

### IPv6

- [ ] IPv6 либо маршрутизируется в туннель, либо блокируется — но не остаётся
      «мимо». Это классическая утечка: IPv4 в туннеле, IPv6 напрямую
- [ ] Проверено в сети с работающим IPv6, а не только там, где его нет

### Обрыв и переходы

- [ ] При падении ядра трафик **блокируется**, если включён kill switch
- [ ] При падении ядра с выключенным kill switch пользователь **видит** разрыв
- [ ] Смена Wi-Fi ↔ мобильная сеть не роняет трафик наружу в момент перехода
- [ ] Выход из сна не оставляет окно, в котором трафик идёт мимо
- [ ] Перезагрузка устройства с включённым автозапуском не даёт окна утечки

### Собственный трафик приложения

- [ ] Обновление подписки не уходит в неработающий туннель
- [ ] Запросы E-1, E-2, E-3 идут туда, куда заявлено, и никуда больше
- [ ] Приложение исключено из собственного туннеля там, где это нужно

### Локальная сеть

- [ ] Локальные адреса ходят напрямую, если так настроено
- [ ] `strict_route` включён — обход туннеля через явную привязку к интерфейсу
      невозможен

## Управляющий канал на десктопе

Служба или хелпер работает с повышенными правами и принимает команды от UI. Это
самая опасная поверхность атаки в проекте: получив к ней доступ, локальный
злоумышленник управляет сетью машины.

Требования:

1. **Только loopback.** `127.0.0.1` на Windows, unix-сокет на macOS и Linux.
   Никогда `0.0.0.0`, никогда порт наружу.
2. **Токен обязателен.** Генерируется при старте службы, хранится в файле с правами
   только для текущего пользователя. Запрос без валидного токена отклоняется.
3. **Проверка вызывающего** там, где ОС позволяет: код подписи клиента на macOS,
   UID пира на unix-сокете.
4. **Минимальный набор команд.** Служба принимает конфиг и команды start/stop/reload.
   Она **не** выполняет произвольные пути, команды или скрипты, полученные от UI.
5. **Валидация конфига в службе**, а не только в UI. UI может быть подменён.

## Цепочка поставок

Открытый код ничего не стоит, если бинарник собран из чего-то другого.

- [ ] `pubspec.lock` и `go.sum` **закоммичены**
- [ ] Версия sing-box пинится точно, бамп — отдельным PR (правило R8)
- [ ] Dependabot включён, обновления идут отдельными PR с ревью
- [ ] Новая зависимость проходит проверку: лицензия совместима с GPLv3, автор
      узнаваем, пакет не тянет сеть без нужды
- [ ] **Воспроизводимая сборка Android** — приоритетная задача к 1.0. Для клиента,
      которому доверяют весь трафик, это главный аргумент доверия
- [ ] Релизные артефакты сопровождаются контрольными суммами
- [ ] Ключи подписи не покидают GitHub Secrets и локальную машину владельца

## Приватность как продукт

Что мы можем честно написать в сторе и в README:

- **Не собираем ничего.** Ни аналитики, ни идентификаторов, ни crash-репортов.
- **Нет серверов.** У проекта нет бэкенда, которому можно было бы что-то отправить.
- **Нет аккаунтов.** Регистрироваться негде.
- **Три исходящих запроса** — все опциональные, все по действию пользователя,
  все перечислены на одном экране настроек.
- **Открытый код и воспроизводимая сборка** — это можно проверить, а не поверить.
