## Правило, по которому этот план написан

**Ни один шаг не закрывается по коду возврата.** Каждый закрывается проверкой
результата на диске или на устройстве. Это не педантизм: за эту ночь
`sdkmanager` уже отрапортовал `ok` по семи пакетам подряд и вернул `0`,
не установив ни одного байта. Если бы шаг был закрыт по exit-коду, сборка упала
бы через час в Gradle с невнятной ошибкой, и искать причину пришлось бы с конца.

## Ш3 · Правка под реальный API libbox  ⏳

Агентам был передан `PlatformInterface` по памяти — он оказался неточным.
Факты вычитаны из исходников и лежат в
[13-libbox-reference.md](13-libbox-reference.md). Что править:

1. **Kotlin** — 15 методов интерфейса ровно по сигнатуре; несуществующих
   `packageNameByUid` и `writeLog` в природе нет.
2. **Обратный поток на Android** — `CommandClient` внутри libbox, а не Clash API.
   Clash остаётся только для десктопа.
3. **Смена узла** — `SelectOutbound(groupTag, outboundTag)`, без пересборки конфига.
4. **Маршруты и per-app** — считает sing-box, Kotlin только перекладывает
   `TunOptions` в `VpnService.Builder`.
5. **Build-теги** — обязательны `badlinkname`, `tfogo_checklinkname0` и
   `-checklinkname=0`, иначе не слинкуется на современном Go.
6. **`go mod tidy` не принимает `-tags`** — только через `GOFLAGS=-tags=...`,
   иначе `go.sum` недосчитается модулей под `with_clash_api`, `with_quic`,
   `with_naive_outbound`, и падение вылезет на компиляции.
7. **Схема конфига** — в TUN-инбаунде `inet4_address`/`inet6_address` слиты в
   `address`, `inet4_route_address` → `route_address`. Старые имена не вызывают
   ошибку валидации, они просто игнорируются.
8. **Шифрование БД** — по [ADR-0007](adr/0007-database-encryption.md):
   `sqlcipher_flutter_libs` и `sqlite3_flutter_libs` объявлены EOL, креды уходят
   в Keystore через secure storage, в SQLite остаются метаданные.

**Закрыт, когда:** Kotlin компилируется против настоящего `libbox.aar`, а не
против выдуманного интерфейса.

## Ш6 · `libbox.aar`  ⏳

Самый рискованный шаг: если `gomobile bind` не соберётся на Windows, запасной
путь — сборка AAR на Linux-раннере в GitHub Actions. Это в любом случае нужно

**Закрыт, когда:** `apps/commy/android/app/libs/libbox.aar` существует и Gradle

---

### Долг, найденный при первой сборке

**Плагины применяют Kotlin Gradle Plugin по-старому.** Flutter 3.44.8 предупреждает:

```
WARNING: Your app uses the following plugins that apply Kotlin Gradle Plugin (KGP):
file_picker, mobile_scanner, package_info_plus, share_plus
Future versions of Flutter will fail to build if your app uses plugins that apply KGP.
```

Сейчас собирается, но это отложенная поломка. Действие — следить за апдейтами
этих четырёх пакетов и обновиться, когда они переедут на Built-in Kotlin. Своими
силами не чинится: правка нужна в самих плагинах.

**Кеш сборки Gradle выключен и включать его на Windows нельзя.** Упаковка дерева
результатов вызывает `stat()` за POSIX-правами, которых в NTFS нет, и сборка
падает на пятнадцатой минуте с `Could not get file mode for R.jar`. Инкрементальная
сборка работает; теряется только переиспользование между сборками. На Linux-раннере
в CI ограничения нет.

### Риск, который вылезет именно здесь

`package:sqlite3` 3.x собирает нативную библиотеку **build hooks**'ами
(`hooks` + `native_toolchain_c`). Это относительно свежая инфраструктура Dart, и
на части версий Flutter она требует явного включения. Если сборка APK упадёт на
чём-то вида «native assets» или «build hook failed» — причина здесь, а не в
нашем коде.

Запасной путь, если хуки не поедут: `sqflite` с ручным SQL вместо drift.
Это дороже по объёму работы, но не меняет [ADR-0007](adr/0007-database-encryption.md) —
креды всё равно живут в Keystore, а не в базе.

## Ш8 · Живой туннель  ⏳

Единственный шаг, который **нельзя закрыть без владельца**: нужна настоящая
подписка (remnawave или любая другая), чтобы проверить, что трафик реально идёт.
Синтетика здесь ничего не доказывает — «APK собирается» и «VPN работает» это
разные утверждения, и путать их нечестно.

Что проверяем на устройстве:
- импорт подписки, разбор `subscription-userinfo`, квота и срок;
- подключение → `checking` → `connected`, IP сменился;
- переживание переключения Wi-Fi ↔ мобильная сеть без переподключения;
- переживание сна и Doze;
- отказ в системном диалоге VPN даёт понятную ошибку, а не тишину.
