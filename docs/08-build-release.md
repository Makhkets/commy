# 08 · Сборка и релизы

## Матрица CI

GitHub Actions. Раннеры распределены по тому, что физически может собрать каждый:

| Workflow | Раннер | Триггер | Что делает |
|---|---|---|---|
| `ci.yml` | ubuntu | PR, push | `melos analyze`, `melos test`, golden-тесты |
| `core.yml` | ubuntu + macos | изменения в `core/**` | Сборка ядра под все таргеты, артефакты в кеш |
| `android.yml` | ubuntu | тег, ручной | AAB + **один APK** (`arm64` + `arm`, правило R11), подпись, проверка бюджета размера |
| `ios.yml` | macos | тег, ручной | IPA, fastlane, TestFlight |
| `windows.yml` | windows | тег, ручной | MSIX + portable zip + манифест WinGet |
| `macos.yml` | macos | тег, ручной | Universal DMG, подпись, нотаризация |
| `linux.yml` | ubuntu | тег, ручной | AppImage, `.deb`, `.rpm`, Flatpak |
| `nightly.yml` | все | ежедневно | Сборки из `main` с пометкой «без гарантий» |

### Сборка Go-ядра — узкое место

Ядро собирается **до** приложения и кешируется по хешу `go.sum` + версии sing-box.
Без кеша каждый билд платит несколько минут за `gomobile bind`.

```
core.yml
  ├─ ubuntu  → android (.aar), linux (.so), windows (.dll, кросс-компиляция)
  └─ macos   → apple (.xcframework), macos (.dylib)
       │
       ▼
   артефакты → скачиваются платформенными workflow
```

Правило R8: бамп версии sing-box — **отдельный PR** с полным прогоном матрицы, а не
попутное изменение.

> Это делается **до** первой публикации, а не после.

## Дистрибуция

### Android

| Канал | Приоритет | Заметки |
|---|---|---|
| **GitHub Releases** | Основной | **Один APK** и `SHA256SUMS.txt` — больше в релизе ничего нет. Работает всегда, ни от кого не зависит |
| **F-Droid** | Основной | Родная среда для GPL-проекта. Требует воспроизводимой сборки и метаданных в репозитории |
| **Google Play** | Дополнительный | Шире охват, но VPN-приложения проверяют строго и могут снять |

Play — **не** основной канал сознательно: проект не должен зависеть от чужой
модерации.

#### Размер APK — бюджет, а не пожелание (правило R11)

APK со страницы релизов скачивается ровно таким, каким собран: между GitHub и
телефоном его никто не сжимает, и качают его нередко через то самое
соединение, которое приложение должно починить. Поэтому размер файла — это
свойство продукта, и у него есть бюджет.

| Файл | Размер (2026-09-18) | Бюджет |
|---|---|---|
| **APK релиза** — `arm64-v8a` + `armeabi-v7a`, единственный на странице | 51,1 МБ | 56 МБ |
| `arm64-v8a` отдельно (`--split-per-abi`, не публикуется) | 27,6 МБ | 32 МБ |
| `armeabi-v7a` отдельно | 27,1 МБ | 31 МБ |
| `x86_64` отдельно — эмуляторы | 29,0 МБ | 34 МБ |

**Почему один файл, а не три по 27 МБ.** Решение владельца от 2026-09-18:
на странице релизов лежало три APK, и люди не понимали, какой качать. Один
файл вдвое тяжелее каждого из них, и это осознанная цена за то, что выбирать
не надо. Чтобы она не была больше необходимого, APK собирается под две
архитектуры, которые бывают у телефонов, и **не несёт ничего для `x86_64`**:
`build.gradle.kts` читает `target-platform` и пакует нативные библиотеки
только названных ABI. Без этого ядро `libbox.so` под x86_64 (13 МБ) ехало бы
в APK, где нет движка, способного его загрузить. Сторож проверяет и это.
`.aab` и `libbox.aar` в релиз не кладутся — это не файлы для пользователя;
они остаются артефактами запуска workflow.

Сторож — `scripts/check_apk_size.sh`; релизный workflow зовёт его до сборки
артефактов. Бюджет = измеренный размер + ~10 %. Нужно больше — число
поднимается **в том же коммите**, и сообщение коммита говорит, на что ушли
байты: дифф этого скрипта и есть история веса приложения.

**Как было 202 МБ и куда они делись.** Никто не решал, что приложение должно
столько весить, — просто никто не смотрел:

| Что | Было | Стало |
|---|---|---|
| Универсальный APK — приложение трижды, по копии ядра, движка и снимка Dart на каждый ABI, включая `x86_64` | 202 МБ | один APK под `arm64` + `arm`, 51 МБ |
| Нативные библиотеки лежали в APK несжатыми (`useLegacyPackaging = false`): 66 из 69 МБ | `libbox.so` 39 МБ | сжаты: `libbox.so` 13 МБ на ABI |
| `lucide_icons_flutter` объявляет семь шрифтов — по одному на толщину штриха, — и Flutter кладёт в сборку все | 6 лишних начертаний, 2,6 МБ | шрифт вендорен в `commy_ui`, после tree-shaking — 11 КБ |

**Цена сжатия библиотек** — на устройстве: установщик распаковывает их рядом с
APK, так что установленный размер вырастает примерно на столько же, на сколько
сократилась загрузка. Платится один раз, при установке; на скорость запуска не
влияет ни в ту, ни в другую сторону. Для AAB всё наоборот — Play сам сжимает
загрузку и отдаёт сплиты под устройство, поэтому в бандле библиотеки остаются
несжатыми (`useLegacyPackaging = !isBundleTask`).

**Что ещё можно снять, но это решение владельца** (CLAUDE.md §7):

- `mobile_scanner` везёт с собой модель ML Kit для QR: `libbarhopper_v3.so` +
  модели ≈ 2,9 МБ в APK. «Небандленный» вариант берёт модель у Google Play
  Services — минус ~2,5 МБ, но сканер перестаёт работать без GMS (Huawei,
  de-Googled) и модель скачивает Google. Для этого проекта — скорее нет.
- Inter ×3 и JetBrains Mono ×2 лежат целиком (все письменности), ≈ 0,9 МБ в
  APK. Подмножество «латиница + кириллица» сняло бы около 0,6 МБ; нужен
  `pyftsubset` и решение по дизайн-ассетам.
- Тег сборки ядра `with_clash_api` на Android не используется (ADR-0005);
  без него `libbox.so` легче примерно на мегабайт. Набор тегов согласован с
  docs/13 — менять вместе с ним.

### iOS

**App Store** — единственный реальный путь. Лицензионный нюанс GPL × App Store
разобран в [11-licensing.md](11-licensing.md). Запасной путь (TestFlight, сайдлоад)
готовится заранее, а не в момент проблемы.

Что понадобится для ревью — держим готовым в репозитории:

- объяснение, что приложение **не предоставляет** VPN-сервис и подключается только
  к серверам, которые ввёл пользователь;
- подтверждение, что встроенных конфигов нет (при первом запуске список пуст);
- заполненная форма конфиденциальности: **данные не собираются**;
- ссылка на исходный код;
- демо-конфиг для ревьюера, иначе он не сможет проверить приложение.

Последний пункт легко забыть, а без него ревьюер видит пустой экран и отклоняет.

### Windows

| Канал | Заметки |
|---|---|
| GitHub Releases | MSIX (со службой) + portable zip |
| WinGet | Манифест в `microsoft/winget-pkgs` |
| Microsoft Store | Позже, если появится смысл |

**SmartScreen.** Неподписанный `.exe` встречает пользователя красным окном
«Windows защитила ваш компьютер». Варианты:

1. **Не подписывать** — бесплатно, но каждый пользователь видит предупреждение.
2. **OV-сертификат** — дешевле, но репутация SmartScreen набирается загрузками, то
   есть первые месяцы предупреждение всё равно есть.
3. **EV-сертификат** — репутация сразу, но дорого и требует токен.

Для опенсорса без бюджета: начинаем с (1), честно предупреждаем в README и даём
контрольные суммы. К (2) или (3) — когда появится смысл.

## Версионирование

**SemVer.** `MAJOR.MINOR.PATCH`, тег `v1.2.3`.

- `MAJOR` — несовместимые изменения формата данных, требующие миграции.
- `MINOR` — новые функции. Новая платформа — это `MINOR` (1.1 = Windows).
- `PATCH` — исправления.

`versionCode` для Android и `CFBundleVersion` для iOS выводятся из тега
автоматически, чтобы не расходиться.

## Процесс релиза

```
1. Заморозка: PR только с исправлениями
2. Обновить CHANGELOG.md (Keep a Changelog)
3. Прогнать чек-лист безопасности из 09-security-privacy.md
4. Прогнать ручные сценарии из 10-testing.md на реальных устройствах
5. Тег vX.Y.Z → CI собирает всё
6. Проверить артефакты руками: установить, подключиться
7. Черновик релиза на GitHub: заметки + контрольные суммы
8. Раскатка по каналам
9. Публикация релиза
```

Шаг 6 не пропускается. Зелёный CI не означает, что приложение устанавливается и
работает.

## Воспроизводимые сборки

Приоритетная задача к 1.0 для Android.

Для клиента, которому доверяют весь трафик, воспроизводимость — **главный аргумент
доверия**. Открытый код без неё доказывает только то, что где-то лежит исходник;
воспроизводимость доказывает, что именно из него собран APK у вас в руках.

Что требуется:

- зафиксированные версии Flutter (FVM), Go, Android SDK и NDK;
- `pubspec.lock` и `go.sum` в репозитории;
- отсутствие меток времени и путей сборочной машины в артефакте;
- документированная процедура сборки, которую может повторить посторонний;
- сверка хешей сторонним человеком перед объявлением о воспроизводимости.

Это же требование F-Droid для их сборочной системы — то есть работа окупается дважды.
