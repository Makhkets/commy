# 03 · Туннель на каждой платформе

> 🛑 **Прежде чем писать хоть строчку Kotlin или Swift — прочитай
> [13-libbox-reference.md](13-libbox-reference.md).**
>
> Этот документ описывает **замысел**. Точный API — там, и он вычитан из
> собранного нами `libbox.aar` через `javap`, а не по памяти и не по статьям.
> Полный дамп сигнатур — [libbox-java-api.txt](libbox-java-api.txt).
>
> Три вещи, на которых ошибается любая реконструкция по памяти:
> 1. **Функции `NewService` не существует.** Туннель поднимается через
>    `CommandServer.startOrReloadService(configJSON, null)`.
> 2. **Методов `packageNameByUid`, `writeLog`, `usePlatformDefaultInterfaceMonitor`
>    в `PlatformInterface` нет.** Там ровно 15 методов, они перечислены в справочнике.
> 3. **Смена сети и Doze не рестартят сервис**: `updateDefaultInterface(...)` +
>    `CommandServer.resetNetwork()`, и `pause()` / `wake()` соответственно.
>
> Расхождение с этим списком ломает сборку на линковке, а не в рантайме.

Здесь живёт вся платформенная специфика. Если в фиче-коде появляется
`if (Platform.isX)` для чего-то связанного с сетью — значит, что-то из этого
документа протекло наверх.

Общая схема на всех платформах одна:

```
Flutter UI  ──►  CoreClient  ──►  [граница процесса?]  ──►  ядро sing-box
                                                              │
                                                              ▼
                                                      TUN-дескриптор от ОС
```

Отличается только **как получить дескриптор** и **есть ли граница процесса**.

## Android

**Статус:** M1 · первая цель
**Граница процесса:** нет — ядро в процессе приложения

### Как работает

`CommyVpnService : VpnService` — foreground-сервис. Последовательность:

1. Dart зовёт `CoreClient.start(config)` → `MethodChannel`.
2. Kotlin проверяет разрешение: `VpnService.prepare()`. Если не выдано —
   системный диалог; отказ превращается в `CommyFailure.permissionDenied()`.
3. Сервис запускается в foreground с постоянным уведомлением (обязательно
   на Android 8+, иначе система убьёт сервис).
4. Kotlin создаёт `libbox.NewService(configJSON, platformInterface)` и стартует.
5. `libbox` через наш `PlatformInterface.openTun()` просит дескриптор — Kotlin
   строит `VpnService.Builder` и отдаёт `ParcelFileDescriptor`.

### `PlatformInterface` — что обязаны реализовать

| Метод | Реализация на Android |
|---|---|
| `openTun` | `VpnService.Builder`: адреса, MTU, DNS, маршруты, per-app списки |
| `autoDetectInterfaceControl` | `VpnService.protect(fd)` — иначе трафик самого ядра уйдёт в туннель и получится петля |
| `findConnectionOwner` | `ConnectivityManager.getConnectionOwnerUid()` (API 29+) для правил по приложениям |
| `packageNameByUid` / `uidByPackageName` | `PackageManager` |
| `usePlatformInterfaceGetter` | `ConnectivityManager.NetworkCallback` — отслеживание смены сети |
| `readWIFIState` | SSID/BSSID для правил «дома не туннелировать» |
| `systemCertificates` | Системное хранилище доверия |

### Per-app split tunneling

`Builder.addAllowedApplication()` / `addDisallowedApplication()`. **Взаимоисключающие**
— либо белый, либо чёрный список, смешивать нельзя. UI обязан это отражать
переключателем режима, а не двумя независимыми списками.

Собственный пакет **всегда** исключается — иначе обновление подписки пойдёт через
туннель, который ещё не работает.

### Специфика Android

- **Always-on VPN + Block connections without VPN** — системный kill switch.
  Приложение не может включить его само, но обязано корректно работать в этом
  режиме и подсказать пользователю путь в настройки.
- **Battery optimization.** Постоянный сервис попадает под Doze. Просим исключение
  явно, с объяснением, а не молча.
- **Смена сети** Wi-Fi ↔ мобильная — не переподнимаем туннель, а сообщаем ядру
  через `PlatformInterface`. Пересоздание TUN рвёт соединения без нужды.
- **Android 14+** — тип foreground-сервиса `specialUse` или корректный
  `FOREGROUND_SERVICE_*` permission, иначе краш при старте.

### Сборка

`gomobile bind -target=android -androidapi 21` → `libbox.aar` → зависимость модуля
`native/android`.

## iOS · macOS (App Store)

**Статус:** M4 · главный риск проекта
**Граница процесса:** да — Network Extension

### Как работает

Отдельный target `CommyTunnel` — `NEPacketTunnelProvider`. Приложение и
расширение — **разные процессы** с разной памятью.

1. Приложение через `NETunnelProviderManager` сохраняет конфигурацию и стартует
   туннель.
2. Система поднимает процесс расширения.
3. Расширение читает конфиг из общего контейнера **App Group** и запускает
   `libbox` внутри себя.
4. Расширение вызывает `setTunnelNetworkSettings` и получает `packetFlow`.
5. UI и расширение общаются через **unix-сокет в контейнере App Group** по
   протоколу `libbox.CommandClient`.

### Лимит памяти 50 MiB — правило R7

Начиная с iOS 15 packet tunnel provider ограничен **50 MiB**. (Исторически было
5–6 МБ, затем 15 МБ в iOS 10.) Превышение = jetsam-kill с `per-process-limit`,
то есть туннель просто падает, без внятной ошибки пользователю.

Следствия для кода:

- В расширении **не должно быть** ничего лишнего: ни Flutter-движка, ни тяжёлых
  библиотек, ни кеша конфигов в памяти.
- Go-рантайму задаётся лимит явно (`libbox.SetMemoryLimit`); GOGC настраивается
  агрессивнее обычного.
- TUN-стек — **gVisor**, не system: предсказуемее по памяти.
- Большие правила маршрутизации (geoip/geosite) грузятся с диска по мере
  надобности, а не целиком в RAM.
- Каждый PR, трогающий target расширения, проверяется профайлером памяти на
  реальном устройстве. Apple прямо предупреждает не хардкодить знание о лимите —
  единственный способ убедиться — измерить на реальных устройствах и версиях ОС.

### Что нужно от Apple

| Что | Комментарий |
|---|---|
| Apple Developer Program | $99/год, обязателен — без него Network Extension не подписать |
| Entitlement `com.apple.developer.networking.networkextension` | Со значением `packet-tunnel-provider` |
| App Group | Общий контейнер для сокета и конфига |
| Ревью App Store | VPN-приложения проверяют пристально; см. ниже |

### Ревью App Store — что говорить

Apple требует от VPN-приложений раскрывать, куда идёт трафик, и запрещает сбор
данных пользователя. Наша позиция в форме проверки предельно выгодна:

- приложение **не предоставляет** VPN-сервис — оно подключается только к серверам,
  которые ввёл сам пользователь;
- встроенных конфигов нет — при первом запуске список пуст;
- никакой аналитики и сбора данных;
- исходный код открыт, ссылка прилагается.

Готовим текст объяснения заранее и держим его в репозитории
(см. [08-build-release.md](08-build-release.md)).

Отдельно: лицензионный нюанс GPL × App Store разобран в
[ADR-0003](adr/0003-gplv3-license.md).

### Специфика Apple

- **On-demand rules** (`NEOnDemandRule`) — автоподключение по SSID или типу сети.
  Нативная фича, аналога на Android нет.
- **`includeAllNetworks`** — тот самый kill switch. Ломает часть локального
  трафика, поэтому только по явному включению пользователем.
- macOS в App Store использует **тот же код** расширения (`#if os(macOS)` для
  различий). Вне App Store — другой путь, см. следующий раздел.

### Сборка

`gomobile bind -target=ios,iossimulator,macos` → `Libbox.xcframework`.

## Windows

**Статус:** M5
**Граница процесса:** да — служба с правами администратора

### Как работает

Создание сетевого адаптера требует прав администратора. Просить UAC при каждом
подключении — неприемлемо. Значит, служба.

```
Flutter (обычные права)
   │  TCP 127.0.0.1:<порт> + токен
   ▼
CommyService (LocalSystem, ставится инсталлятором)
   │
   ├─ commy_core.dll  (ядро sing-box)
   └─ Wintun adapter
```

- Служба ставится **один раз** инсталлятором, UAC — только при установке.
- При старте служба генерирует токен и пишет его в файл, доступный только текущему
  пользователю. Приложение читает токен и предъявляет при каждом запросе.
- Слушаем **строго `127.0.0.1`**, порт случайный. Никаких `0.0.0.0`.
- Приложение умеет пережить отсутствие службы: показывает понятное состояние
  «служба не запущена» с кнопкой запуска, а не молча не подключается.

### Портативный режим

Обязателен — аудитория его ждёт. Без службы, с разовым UAC на запуск. Всё в одной
папке, ничего в реестре. Флаг в UI показывает, в каком режиме приложение работает.

### Специфика Windows

- **Wintun** — драйвер от авторов WireGuard, входит в состав sing-box.
- **SmartScreen.** Неподписанный `.exe` встречает пользователя красным окном.
  Сертификат подписи кода стоит денег; варианты разобраны в
  [08-build-release.md](08-build-release.md).
- **Автозапуск** — `launch_at_startup`, но осмысленно только вместе со службой.
- **Трей обязателен.** Закрытие окна сворачивает в трей, не выключает туннель.

## macOS (вне App Store)

**Статус:** M6
**Граница процесса:** да — привилегированный хелпер

Для дистрибуции DMG (не через стор) System Extension недоступен без отдельного
entitlement, поэтому используем привилегированный хелпер.

- **`SMAppService`** (macOS 13+) регистрирует хелпер-демон.
- Хелпер создаёт `utun` и хостит ядро.
- IPC — unix-сокет в `/var/run/commy.sock` с проверкой кода подписи клиента.
- Приложение подписывается и **нотаризуется**, иначе Gatekeeper не пустит.

Приоритет дистрибуции: сначала DMG (быстрее и без ревью), затем App Store как
второй канал, переиспользующий код iOS-расширения.

## Linux

**Статус:** M7
**Граница процесса:** да — хелпер с `CAP_NET_ADMIN`

```
Flutter (обычный пользователь)
   │  unix-сокет /run/commy/ctl.sock
   ▼
commy-helper  (systemd unit, CAP_NET_ADMIN)
   └─ libcommy_core.so + /dev/net/tun
```

- Авторизация на запуск/остановку — через **polkit**, а не setuid. Setuid-бинарник
  в сетевом приложении — плохая идея.
- Права на сокет ограничены группой `commy`; пользователь добавляется в неё при
  установке пакета.

### DNS на Linux — отдельная головная боль

Единого способа нет, поэтому детектируем и поддерживаем три:

| Среда | Как управляем DNS |
|---|---|
| systemd-resolved | D-Bus `SetLinkDNS` на интерфейсе туннеля — правильный путь |
| NetworkManager | Через его D-Bus API |
| Голый `/etc/resolv.conf` | Правка с бэкапом и **гарантированным** восстановлением |

Третий случай самый опасный: если приложение упало, не восстановив файл, у
пользователя сломан DNS во всей системе. Нужен watchdog в хелпере, который
восстанавливает состояние при неожиданном завершении.

### Специфика Linux

- **Форматы пакетов:** AppImage (универсально), Flatpak (Flathub), `.deb`, `.rpm`.
  Flatpak-песочница требует отдельной работы с правами на сеть.
- **Трей** через `tray_manager` работает не во всех окружениях (Wayland, GNOME без
  расширения). Приложение обязано оставаться пригодным без трея.
- **Wayland vs X11** — Flutter Linux ведёт себя по-разному. Тестируем оба.
