# ADR-0014 · Селектор стартует на выборе пользователя, а не на кэше ядра

**Статус:** принято · 2026-09-23 агентом по задаче владельца «туннель не
работает, почини». Откатывается удалением одной правки в
`core/cmd/overlaygen/main.go`.
**Контекст правил:** [R8](../../CLAUDE.md) — «sing-box не обновляем мимоходом»

---

## Проблема

Найдена на эмуляторе, пока проверялась правка версии REALITY
([ADR-0013](0013-reality-client-version.md)) на узлах владельца. Выбран
Finland, в чипе под кнопкой — Finland, а ядро после подключения пошло через
узел стенда, выбранный днём раньше: в логе `dial tcp 10.0.2.2:18443`.

sing-box `protocol/group/selector.go`, `Start()`:

```go
if s.Tag() != "" {
	cacheFile := service.FromContext[adapter.CacheFile](s.ctx)
	...
		selected := cacheFile.LoadSelected(s.Tag())
		if selected != "" { ... s.selected.Store(detour); return nil }
}
if s.defaultTag != "" { ... }
```

При включённом `cache_file` (он у нас включён всегда) селектор стартует на
том, что было выбрано **внутри работающего ядра** в прошлый раз, — это
пишется при каждом переключении сервера на поднятом туннеле, — и читает
`default` из конфигурации, только если кэш пуст. А Commy кладёт выбор
пользователя именно в `default`, при каждом старте, из собственных настроек.

Итог: сервер, выбранный при отключённом туннеле, проигрывал серверу, на
который переключались в прошлой сессии. Чип называл один, трафик шёл через
другой — или через тот, что уже не отвечает. Для пользователя это выглядит
как «подключение не работает».

---

## Решение

**Кэш читается, только если в конфигурации нет `default`.** Одна правка
условия в `Start()` через оверлей сборки. Селекторы Commy всегда задают
`default`, так что их кэш больше не читается; поведение для конфигураций без
`default` — прежнее.

---

## Альтернативы

- **Выбирать узел командой после старта.** Лечит, но между стартом TUN и
  командой есть окно, в котором соединения уходят через чужой сервер.
- **`cache_id` на каждый старт.** FakeIP он не затрагивает, но файл кэша
  растёт на корзину за каждую сессию с переключением.
- **`cache_id` по выбору.** Ломается на цепочке «старт на A, переключение на
  B, позже снова A»: в корзине A лежит B.
- **Выключить кэш.** Теряется сохранённая таблица FakeIP (docs/09, сессия 16).

---

## Как это проверено

- **Тест против библиотеки** — `core/internal/singbox/selector_default_test.go`
  (тег `commy_overlay`, гоняется в CI): настоящий экземпляр sing-box с файлом
  кэша; первая сессия переключается на `b` внутри ядра, вторая стартует с
  `default: a`. Без правки — `b`, с правкой — `a`.
- **Эмулятор** — выбор сервера при отключённом туннеле, затем подключение:
  трафик идёт через выбранный узел (docs/17, «Сессия 17»).

---

## Последствия

- Выбор в приложении — единственный источник правды о сервере.
- Переключение на живом туннеле по-прежнему работает (`SelectOutbound` в
  работающем ядре правка не трогает); после отключения приложение само
  помнит новый выбор и передаст его в следующий старт.
- Правку снять, если sing-box начнёт предпочитать `default` сам.
