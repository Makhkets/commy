# ADR-0004 · Mobile-first порядок выпуска платформ

**Статус:** Accepted
**Дата:** 2026-08-01

## Контекст

Пять платформ нельзя выпустить одновременно. Порядок определяет роадмап, состав
CI на каждом этапе и то, как рано придёт реальная обратная связь.

Две противоположные логики:
- **desktop-first** — быстрее итерации (нет сторов, нет подписи, нет ревью),
  дешевле отладка;
- **mobile-first** — раньше приходит настоящая аудитория, но раньше приходят и
  самые дорогие ограничения платформ.

## Решение

**Android → iOS → Windows → macOS → Linux.**

При этом с самого начала (M0) поддерживаются **два** таргета сборки Go-ядра:
Android и десктоп текущей машины разработчика. Десктоп служит стендом для отладки
логики, не будучи выпускаемым продуктом до M3.

## Альтернативы

**Desktop-first (Windows → Linux → macOS → Android → iOS).** Быстрее в разработке.
Отклонено: основная аудитория таких клиентов — мобильная, и откладывание её на
конец означает год разработки вслепую. Хуже того, iOS в самом конце — это риск
обнаружить архитектурную проблему (лимит памяти расширения, ограничения IPC) тогда,
когда переделывать дороже всего.

**Android → Windows → iOS → macOS → Linux.** Выглядит безопаснее: два «дешёвых»
таргета подряд, iOS отодвинут. Отклонено по той же причине — iOS диктует самые
жёсткие ограничения (50 MiB на расширение, IPC только через App Group, ревью
Apple). Их надо знать до того, как код десктопа затвердеет.

## Последствия

**Стало проще**
- Настоящие пользователи появляются после M1, а не после M5.
- Самое рискованное (iOS) проверяется вторым: если там всплывёт архитектурная
  проблема, десктопный код ещё не написан и подстроится.
- Android и iOS вместе валидируют полный контур `libbox` — дальше десктоп
  переиспользует уже проверенные абстракции.

**Стало сложнее / за что платим**
- **M4 (iOS) — главный риск проекта.** Требует Apple Developer Program ($99/год),
  одобрения entitlement на Network Extension и прохождения ревью. Может занять
  существенно дольше оценки по причинам вне нашего контроля.
- Пока идёт iOS, десктопные пользователи не получают ничего. Митигация:
  публиковать **nightly-сборки** десктопа из CI с явной пометкой «без гарантий»,
  начиная с M2.
- Linux последний — а это платформа, где живёт заметная часть контрибьюторов
  опенсорса. Митигация: с M0 держать CI-джобу сборки Linux зелёной, даже без
  релиза, чтобы код не сгнил.

## Триггер пересмотра

Если к концу M3 доступ к Apple Developer Program не получен — порядок меняется на
`Windows → macOS → Linux → iOS`, чтобы проект не стоял. Это не отменяет ADR, но
требует нового ADR с обоснованием.
