# ADR-0018 · Правки ядра — в копиях модулей вне кеша; Go — поддерживаемая линия

**Статус:** принято · 2026-09-30 агентом по поручению владельца («решения
принимай сам»; сборка сетевого ядра — вопрос CLAUDE.md §7.1 и правила R8,
поэтому отдельным PR со своим прогоном).
**Заменяет часть** [ADR-0010](0010-xhttp-transport.md) о механизме: вместо
`go build -overlay` поверх кеша модулей — копии модулей с правками.
**Контекст правил:** R8 (ядро только через `scripts/build_core.sh`, бамп —
отдельным PR), R6 (ядро несёт весь трафик пользователя).

---

## Что случилось

PR Dependabot #35 (`github.com/miekg/dns` 1.1.72 → 1.1.73) упал в CI на
сборке ядра:

```
go: overlay contains a replacement for …/sing-box@v1.13.16/common/tls/reality_client.go.
Files beneath GOMODCACHE (…/pkg/mod) must not be replaced.
```

Дело не в `miekg/dns`: новая версия требует `go 1.25.0`, CI ставит Go по
директиве `go` из `core/go.mod`, и на Go 1.25 оверлей не работает **вообще** —
проверено на `main`: `GOTOOLCHAIN=go1.25.0 go build -overlay=…` падает с той же
ошибкой. Go с 1.25 проверяет в `work.BuildInit`, что оверлей не подменяет
файлы под `GOMODCACHE`, а все наши правки — это как раз файлы sing-box и
sing-tun в кеше модулей.

Следствие важнее самого PR: ядро собиралось **Go 1.24.7** (релиз
`v0.1.0-alpha.11` — тоже). Линия 1.24 не получает исправлений безопасности с
выхода 1.26 (февраль 2026), а 1.24.7 — к тому же не последний её патч. Этот
код держит TLS, HTTP и DNS каждого соединения пользователя. И любой будущий бамп
зависимости или самого sing-box, требующий Go ≥ 1.25, упёрся бы в ту же стену.

## Решение

1. **`core/cmd/overlaygen` пишет копии, а не оверлей.** Модули, которые
   затрагивают правки (sing-box и sing-tun), копируются из кеша в
   `core/build/_overlay/mod/<модуль>@<версия>/`, правки накладываются на копии
   (та же сверка SHA-256 исходного файла, те же якоря), рядом пишется `go.mod`
   — копия `core/go.mod` с `replace` на эти каталоги по абсолютным путям — и
   `go.sum`. Генератор печатает путь к этому `go.mod`.
2. **Тесты и десктопные сборки** — `go test -modfile=<этот go.mod>` /
   `go build -modfile=…` (CI `core.yml`, `xhttp_interop.sh`,
   `emulator_stand.sh`, комментарии в тестах).
3. **`gomobile`** — из копии `core/` (`core/build/_core`), в которой этот
   `go.mod` лежит как собственный. `gomobile bind` выполняет
   `go list -m -json all` в текущем модуле, переносит `replace` в `go.mod`
   своего временного модуля `gobind` и собирает там; флаг `-modfile` в
   `GOFLAGS` ушёл бы в эту временную сборку и подменил бы её модуль.
4. **`GODEBUG=goindex=0` больше не нужен** (индекс модулей строится только для
   кеша, а копии — не в кеше), и **go-shim для Apple** тоже: он существовал,
   чтобы вернуть `-overlay` в `GOFLAGS`, которые `gomobile` переписывает для
   Apple-целей.
5. **`core/go.mod`: `go 1.26.8`** — последний патч поддерживаемой линии 1.26
   на 2026-09-30 (1.27.1 — тоже поддерживаемая, но линии месяц, а sing-box
   держится на `go:linkname` в рантайм, и свежий релиз Go — лишний риск для
   ядра). CI ставит Go по этой директиве (`go-version-file`), локально `go`
   скачивает тулчейн сам (`GOTOOLCHAIN=auto`).

`core/go.mod` по-прежнему называет опубликованные `sing-box v1.13.16` и
sing-tun без `replace` — `replace` живут только в сгенерированном файле.

## Отвергнутые варианты

- **Остаться на Go 1.24 и закрепить последний патч 1.24.x.** Линия без
  исправлений безопасности; и тупик для каждого следующего бампа.
- **Форк sing-box с правками.** Причины те же, что в ADR-0010: `go.mod`
  перестаёт говорить, какое ядро мы везём, и форк надо сопровождать.
- **`go.work` с `replace`.** `gomobile` собирает во временном каталоге,
  которого нет в `use` рабочего пространства; `GOWORK` из окружения ломает эту
  сборку так же, как `-modfile`.
- **Временно править `core/go.mod` на время сборки.** Прерванная сборка
  оставила бы в рабочем дереве `replace` на локальные каталоги.

## Как проверено

- `go test` с `-modfile` (XHTTP сквозной, sing-tun, sing-box, контракт
  `core_accepts_test.go`) — зелёные на Go 1.24.13 **и** на Go 1.26.8;
  `go test -race ./...`, `go vet` с тегами ядра, типизация под
  android/arm64 — зелёные на 1.26.8.
- `scripts/build_core.sh android` на Go 1.26.8 собрал `libbox.aar` под три ABI
  (в `libbox.so` зашито `go1.26.8`), маркер XHTTP найден в каждой библиотеке
  (проверка `verify_xhttp_in`).
- `scripts/xhttp_interop.sh` — ядро из копий против настоящего Xray: 30 из 30
  сценариев (XHTTP во всех режимах и версиях HTTP, REALITY, второй маршрут
  скачивания) и против Xray 26.3.27, и против Xray 26.9.9 — того, что требует
  современный ClientHello REALITY.
- Живой туннель на эмуляторе с этим ядром — docs/17, «Сессия 22».

## Последствия

- Бамп sing-box по-прежнему включает перебазирование правок: `overlaygen`
  остановит сборку на изменившемся файле или версии sing-tun.
- Следующий переход Go (1.27, затем 1.28) — отдельным PR с тем же прогоном:
  `go vet`/тесты/сборка AAR/interop/эмулятор.
- Dependabot-бампы, требующие Go 1.25+, больше не ломают сборку ядра.
