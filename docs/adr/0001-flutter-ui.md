# ADR-0001 · Flutter как UI-фреймворк

**Статус:** Accepted
**Дата:** 2026-08-01

## Контекст

Цель — одно приложение на Android, iOS, Windows, macOS и Linux. Проект
опенсорсный, команда маленькая. Значит, пять отдельных нативных UI отпадают по
арифметике: пятикратный объём работы, пятикратное количество багов, пять разных
релизных циклов.

Отдельное ограничение: на **любой** платформе туннель всё равно требует нативного
кода (системный VPN API нельзя вызвать из кроссплатформенного рантайма). Значит,
критерий выбора — не «избавит ли фреймворк от нативного кода» (не избавит ни один),
а «насколько дёшево он с этим нативным кодом состыкуется, и что он стоит на
десктопе».

## Решение

**Flutter** для UI и всей бизнес-логики. Нативный код — только тонкий слой
туннеля на каждой платформе, общающийся с Dart через platform channels и FFI.

## Альтернативы

**Compose Multiplatform.** Плюс: один язык (Kotlin) с Android-туннелем, отличная
экосистема JetBrains, iOS-таргет стабилизировался. Минус, который перевесил:
десктопная сборка тянет JVM — 80–150 МБ дистрибутива и заметный расход RAM
у приложения, которое должно тихо висеть в трее сутками. Для VPN-утилиты это
неправильный профиль. Плюс cinterop из Kotlin/Native к Go-библиотеке на iOS
болезненнее, чем Swift ↔ gomobile.

**Tauri v2.** Плюс: самые лёгкие десктопные бинарники (~10 МБ), веб-UI итерируется
быстро. Минус: мобильная часть Tauri 2 молода, а интеграция iOS Network Extension
практически не имеет прецедентов. Риск застрять на iOS с непроверенной технологией
слишком высок для проекта, где iOS — обязательная цель.

**React Native.** Мобайл хорош, десктоп слаб: `react-native-windows` и `-macos`
живут своей жизнью, Linux не поддерживается вообще. Не закрывает задачу.

**Нативно на каждой платформе (путь Happ).** Лучший возможный UX и минимальный вес.
Отклонено по объёму работ — см. Контекст.

## Последствия

**Стало проще**
- Один UI, одна дизайн-система, один набор виджет-тестов на пять платформ.
- Нативные бинарники без рантайма-прослойки: холодный старт и память приемлемы
  для фонового приложения.
- Есть прямые прецеденты (Hiddify, Karing) — известно, что связка работает.

**Стало сложнее / за что платим**
- Ещё один язык в проекте. Итого: Dart + Go + Kotlin + Swift + C++/C. Это цена
  кроссплатформенности с системным туннелем, а не цена Flutter.
- Нативные интеграции требуют ручной работы на каждой платформе — Flutter их не
  устраняет, только изолирует за одним Dart-интерфейсом.
- Golden-тесты чувствительны к версии Flutter → обязателен пин через FVM.
- Linux-десктоп у Flutter — наименее укатанная цель; закладываем запас времени
  в M7.
