# ADR-0002 · sing-box как сетевое ядро

**Статус:** Accepted
**Дата:** 2026-08-01

## Контекст

Клиенту нужен движок, который умеет современные прокси-протоколы, поднимает TUN,
разруливает DNS и маршрутизацию. Писать это самостоятельно — не проект, а карьера.
Реальный выбор: sing-box или Xray-core. Оба на Go, оба зрелые, оба массово
используются.

Решающий фактор — не список протоколов, а **стоимость интеграции с системным VPN
API пяти платформ**. Именно здесь тонут проекты такого класса.

## Решение

**sing-box** (SagerNet), встраивается через пакет `experimental/libbox`.
Версия ядра пинится точно; обновление — всегда отдельный PR с полным прогоном
матрицы (правило R8).

## Альтернативы

**Xray-core (MPL-2.0).** Серьёзный кандидат, и на нём построен Happ.

Плюсы, от которых мы отказываемся:
- MPL-2.0 не заражает проект — можно было бы выбрать любую лицензию и не иметь
  вообще никаких вопросов к App Store;
- эталонная реализация VLESS/Reality, всё новое появляется там первым.

Минусы, которые перевесили:
- **нет аналога `libbox`.** Мост к `VpnService` и `NEPacketTunnelProvider` пришлось
  бы писать самим, на каждой платформе, вместе с `tun2socks` (hev-socks5-tunnel) и
  своим протоколом IPC. Оценка: +2–3 месяца до первого рабочего Android-билда;
- нет Hysteria2 и TUIC — а это ровно те протоколы, ради которых сейчас переходят
  на новые клиенты;
- нет готового Clash API — статистику, логи и замер задержки пришлось бы строить с нуля.

**Оба ядра за абстракцией `CoreEngine`.** Честный путь, но: абстракция стоит
времени именно тогда, когда его меньше всего (на старте), она всё равно не спасает
от GPL (sing-box остаётся в сборке), и второй движок неизбежно окажется
второсортным по тестированию. Отложено — см. [01-stack.md](../01-stack.md#что-осознанно-отложено).

## Последствия

**Стало проще**
- `PlatformInterface` даёт готовый контракт для нативного слоя: открыть TUN,
  защитить сокет от петли, найти владельца соединения (per-app правила), отследить
  смену сети.
- `CommandServer`/`CommandClient` — готовый IPC между UI и ядром, включая случай
  «ядро в другом процессе» (iOS NE, Windows-служба).
- Clash API переиспользуется как единый транспорт для статистики/логов/задержки
  на всех платформах.
- Все нужные протоколы — сразу, без интеграционной работы на каждый.

**Стало сложнее / за что платим**
- **GPL-3.0 распространяется на весь проект.** Для опенсорса приемлемо, но требует
  дисциплины: любая новая зависимость проверяется на совместимость с GPLv3.
  Подробности и нюанс App Store — [ADR-0003](0003-gplv3-license.md) и
  [11-licensing.md](../11-licensing.md).
- Мы зависим от темпа и решений апстрима. Ломающее изменение в `libbox` — наша
  проблема. Отсюда правило R8 и пин версии.
- API `libbox` помечен `experimental` — обратная совместимость не гарантирована.
- Формат конфига sing-box становится нашим внутренним контрактом: генератор
  конфига в `commy_config` придётся сопровождать при каждом бампе ядра.
