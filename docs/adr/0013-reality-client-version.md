# ADR-0013 · Версия клиента в REALITY: 26.9.9 вместо 1.8.1

**Статус:** принято · 2026-09-23 агентом по задаче владельца «туннель не
работает, почини». Откатывается удалением одной правки в
`core/cmd/overlaygen/main.go`.
**Контекст правил:** [R8](../../CLAUDE.md) — «sing-box не обновляем мимоходом»

---

## Проблема

На телефоне владельца не подключался ни один REALITY-узел его панели, а Happ
на тех же узлах работал. В логе ядра — `reality verification failed` на
каждом соединении, причём и для современного hello, и для обрезанного
([ADR-0011](0011-reality-client-hello.md)).

Воспроизведено с машины разработки на трёх настоящих узлах тестовым
пользователем панели. Ключ, short id и SNI в ссылках совпадают с конфигом
сервера (публичный ключ пересчитан из `privateKey` профиля). Локальный Xray
26.3.27 с той же мишенью и теми же параметрами клиента пропускает. Узлы же
работают на **Xray 26.7.28**.

Причина — в Xray, `infra/conf/transport_security.go` версии 26.7.28:

```go
} else {
	config.MinClientVer = []byte{26, 3, 27} // change it at your own risk
	// "The default minimal client version is Xray-core v26.3.27, other clients may be refused to connect"
}
```

Если владелец сервера не задал `minClientVer`, REALITY-сервер пропускает
только клиентов, назвавших в зашифрованном session ID версию не ниже 26.3.27.
REALITY-клиент sing-box называет **1.8.1** — это зашито в
`common/tls/reality_client.go`, в том числе в текущей ветке `testing`. Отказ
выглядит как показ сертификата сайта-мишени, отсюда
`reality verification failed`.

| Xray на сервере | Что требует от клиента |
|---|---|
| ≤ 26.3.27 | ничего |
| 26.7.28 | версию ≥ 26.3.27 (умолчание) |
| ≥ 26.9.8 | умолчание снова закомментировано; обязателен X25519MLKEM768 (ADR-0011) |

---

## Решение

**Клиент называет себя 26.9.9** — релизом Xray, чей REALITY-клиент наш теперь
повторяет: тот же hello Chrome с X25519MLKEM768. Правка — ещё одна замена в
том же файле оверлея, что ADR-0011; хэш файла прежний.

Сервер использует версию только в проверке диапазона `minClientVer` /
`maxClientVer` (прочитано в `xtls/reality` обеих используемых версий), так что
число меняет ровно одно: пускают или нет.

---

## Альтернативы

- **Попросить владельцев серверов задать `minClientVer`.** Владелец сервера и
  пользователь приложения — разные люди, а умолчание стоит у всех, кто
  обновился.
- **Бамп sing-box.** Не помогает: апстрим по-прежнему пишет 1.8.1.
- **Называть 26.3.27 — ровно порог.** Проходит сегодня, но это самое
  «старое» из допустимого; следующее поднятие порога снова отрежет клиента.

---

## Как это проверено

- **Три настоящих узла владельца** (Чехия, Нидерланды, Швеция; Xray 26.7.28):
  ядро как есть — `reality verification failed`, с правкой — HTTPS через
  туннель, ответ 204.
- **Тест против библиотеки** — `core/internal/singbox/reality_version_test.go`
  (тег `commy_overlay`, гоняется в CI): REALITY-сервер из `metacubex/utls` с
  порогом 26.3.27. С версией 1.8.1 клиент получает сертификат мишени, с
  правкой — проходит и получает эхо.

---

## Последствия

- REALITY работает на узлах с Xray 26.7.28 — а это любая панель, обновившая
  узлы этим летом.
- Если Xray снова поднимет порог выше 26.9.9, число придётся поднять;
  симптом будет тот же — `reality verification failed` при верных ключах.
- `github.com/metacubex/utls` в `core/go.mod` стал прямой зависимостью (его
  использует тест); версия та же.
