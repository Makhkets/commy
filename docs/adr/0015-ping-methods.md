# ADR-0015 · Пинг: GET через сервер по умолчанию, отдельным экземпляром ядра

**Статус:** принято · 2026-09-23 по задаче владельца: «добавь раздел пинг,
чтобы по умолчанию он через GET пинговал и там был выбор ещё методов пинга
icmp tcp get».
**Контекст правил:** [R1](../../CLAUDE.md) — тишина в сети,
[R11](../../CLAUDE.md) — размер, §5 — публичный API `core/mobile`

---

## Проблема

Список серверов мерился двумя способами, и выбирал их не пользователь, а
состояние туннеля:

- **туннель поднят** — URL-тест работающего ядра (запрос через сервер);
- **туннель снят** — время TCP-рукопожатия с портом сервера из Dart.

Второй способ отвечает не на тот вопрос. REALITY-сервер, который отвергает
этого клиента (ADR-0013), принимает TCP-соединение так же быстро, как рабочий,
и список рисовал ему зелёные 40 мс. А числа нужнее всего именно до
подключения: какой из серверов вообще работает. Happ и INCY по умолчанию
меряют запросом через сервер — и владелец попросил то же, с выбором метода.

---

## Решение

**Раздел «Пинг» в настройках** — `AppSettings.pingMethod`, три значения:

| Метод | Что меряет | Чем |
|---|---|---|
| **GET** (по умолчанию) | рукопожатие с сервером + один запрос через него к адресу проверки | отдельный экземпляр ядра, `core/latency` |
| **TCP** | время, за которое сервер принимает TCP-соединение, напрямую | сокет `dart:io` (`SocketLatencyProbe`) |
| **ICMP** | эхо-запрос к адресу сервера, напрямую | «ping-сокет» Android из Kotlin (`ServerProbes.echo`) |

Метод один на весь прогон и **не зависит от того, поднят ли туннель**. Кнопка
«Проверить» — не пинг: она спрашивает работающее ядро про тот выход, через
который сейчас идёт трафик, и осталась как была.

**GET без туннеля.** `core/latency` поднимает ровно те исходящие, что ему
дали — без входящих, без TUN, без маршрутизации, — делает через каждый GET и
закрывает экземпляр. Конфигурацию собирает `SingBoxConfigBuilder.buildProbe`:
исходящие байт в байт как в туннеле (тот же транспорт, TLS, REALITY,
отпечаток), имена серверов разрешаются прямым резолвером пользователя, как
их разрешает туннель. Лог выключен: это не лог пользователя.

**Как это попадает в приложение.** Функция `URLTestOutbounds` живёт в
собственном пакете `core/mobile`, и gomobile биндит его рядом с libbox в ту
же библиотеку (`io.nekohasekai.mobile.Mobile`). Сначала она была правкой
оверлея внутри libbox — и в AAR не попала: gomobile пишет Java-обёртки по
исходникам на диске, а оверлей видит только компилятор. Функция
скомпилировалась бы в `.so` без единого способа её вызвать.

**DNS в экземпляре замера.** sing-box понимает `local` на Unix как чтение
`/etc/resolv.conf`, которого на Android нет. Туннелю резолвер Android
отдаёт приложение (`AndroidDnsTransport`), а экземпляру замера платформы
нет — и не нужно: `latency.Context` регистрирует для `local` резолвер Go, а
Go на Android резолвит через libc, то есть через netd (`net/conf.go`).

**Таймауты.** GET — 8 с на сервер (рукопожатие плюс запрос по мобильной
сети), TCP и ICMP — 5 с. Замер идёт пулом из шести: следующий сервер
начинается, как только закончился любой, и молчащий сервер держит одну
ячейку, а не всю пачку. `latency.Get` отвечает по дедлайну, даже если
рукопожатие протокола контекст не слушает (так вёл себя SOCKS в тесте —
десять минут).

---

## Почему это не нарушает R1

Каждый метод говорит только с хостом, который ввёл пользователь. TCP и ICMP —
это первый пакет, который отправил бы и connect. GET уходит **через сервер
пользователя**: устройство соединяется с ним, а адрес проверки
(`latencyProbeUrl`) запрашивает уже сервер — ровно как при URL-тесте
работающего ядра, который был и раньше. Все три идут мимо туннеля и при
поднятом туннеле: пакет приложения всегда исключён из него
(`CommyVpnService.applyPackages`).

---

## Альтернативы

- **GET только через работающее ядро.** Так было: до подключения — ничего.
- **Поднимать служебный экземпляр через `CommandServer` libbox.** Один сервер
  команд на процесс, и он принадлежит туннелю; экземпляр замера, который
  ждёт своей очереди за туннелем, — это снова «сначала подключись».
- **Функция в libbox правкой оверлея.** Не получает обёртки gomobile (см.
  выше).
- **ICMP через `InetAddress.isReachable`.** Отвечает `true` и на отказ TCP в
  порт 7 — «доступен» там, где эха не было. Свой ping-сокет честнее и столь же
  короток.

---

## Вес

Код `core/latency` и `core/mobile` — несколько килобайт в `libbox.so` на ABI;
sing-box в библиотеке уже есть целиком. Релизный APK: 53 878 182 → 53 909 486
байт (+31 КБ вместе с ICMP на Kotlin и Dart-частью), 51,4 МБ из 56 (R11).
