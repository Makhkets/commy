# ADR-0017 · Резервная копия: один файл под паролем, Argon2id + ChaCha20-Poly1305

**Статус:** принято · 2026-09-29 агентом по поручению владельца («меня ничего
не спрашивай, принимай решения сам»; новая зависимость — вопрос CLAUDE.md
§7.2, модель угроз — §7.4). Функция G10 из раздела «Релиз 1.0»
([07-roadmap.md](../07-roadmap.md)).
**Контекст правил:** R1 (никакой сети «от себя»), R2 (секреты не в открытом
виде), R3 (логи), R11 (вес APK); [06-data-model.md, «Экспорт»](../06-data-model.md#экспорт):
«полный бэкап — зашифрованный архив, пароль задаёт пользователь; без пароля не
экспортируем»; [00-vision.md](../00-vision.md): «синхронизация через файл (без
облака)».

---

## Зачем

Перенос на новый телефон и переустановка. Самый свежий пример — сам проект:
`v0.1.0-alpha.9` первым подписан ключом проекта и ставится только через
удаление прежней версии, то есть с потерей подписок, серверов и правил.
Android-бэкап выключен сознательно (`allowBackup="false"`,
`data_extraction_rules.xml`): он унёс бы секреты в облако Google. Нужна своя
копия — файл, который пользователь кладёт куда хочет.

## Решение

**Что в копии.** Подписки с URL, **все** серверы с ключами (и из подписок, и
добавленные руками), группы, маршрутизация с правилами по порядку, DNS,
настройки приложения, выбранный сервер, список тегов наборов правил.
Серверы подписок — в копии, а не «URL и обновить»: восстановление работает без
сети (панель может быть закрыта вне туннеля или лежать), а на новом телефоне с
новым HWID панель с лимитом устройств ответила бы заглушкой вместо серверов.

**Чего в копии нет — и почему.**

| Не входит | Почему |
|---|---|
| HWID (`commy.device.id`) | Идентификатор **установки** (ADR-0009). Перенесённый на второй телефон, он сделал бы два устройства одним для панели |
| Ключ БД, кэш конфига, секреты Clash API и хелпера | Принадлежат устройству или выводятся заново |
| Статистика трафика, логи, отказы импорта | Записи о том, что было здесь, а не выбор пользователя |
| Файлы наборов правил | Мегабайты, которые источник E-2 отдаёт снова; загрузка — решение пользователя (R1). После восстановления приложение называет недостающие и ведёт на экран «Наборы правил» |
| Замеренные задержки | Сняты в другой сети, только исказили бы сортировку |

Страж-тест (`commy_data/test/backup/backup_round_trip_test.dart`) требует,
чтобы каждая таблица БД и каждый ключ настроек были явно отнесены к «в копии»
или «не входит, потому что…»: новая таблица без решения роняет тест.

**Восстановление — полная замена**, после вопроса «Заменить всё?» с датой
копии и числами (подписки, серверы, правила). Слияние отвергнуто: настройки,
маршрутизация и DNS — один объект, а для серверов «слить» значит молча решать,
чья подписка главнее. Туннель перед заменой отключается (под kill switch —
блокирующий TUN, ADR-0016), обратно сам не поднимается. Подписки, группы и
серверы меняются **одной транзакцией** (`DriftLibraryStore`): новые ключи в
хранилище — до, строки — одним batch, ненужные ключи — после. Хранилище ключей
не транзакционно, поэтому перед записью запоминается, что лежало под теми же
id (восстановление на тот же телефон переиспользует их все), и при сбое
старой библиотеке возвращаются её ключи. Выбор сервера пишется сразу после
библиотеки, а не последним: сбой на маршрутизации или настройках не оставит
его указывающим на удалённый сервер. HWID и ключ БД не трогаются никогда
(поэтому не `SecretVault.wipe()` + `clearAll()`).

**Экспорт читает строго** (`LibraryStore.readLibrary`). Репозитории при сбое
чтения хранилища ключей отдают серверы без ключей и подписки с обрезанным URL
— экрану так лучше, он покажет хоть что-то. Копии — хуже: она выглядела бы
полной и восстановила бы неработающие серверы. Поэтому здесь такой сбой —
отказ экспорта.

**Обновление подписки, пережившее её.** Фоновое обновление, начавшееся до
восстановления, после ответа панели записало бы старую подписку обратно
(`upsert` создаёт так же охотно, как обновляет). `UpdateSubscriptionUseCase`
теперь переспрашивает хранилище после сетевого запроса: подписки нет или у неё
другой URL — ничего не пишется. Это закрывает и старую гонку «удалил подписку,
пока она обновлялась».

**Заглушка панели после восстановления — поведение, а не ошибка.** На новом
телефоне HWID новый; панель с исчерпанным лимитом устройств на ближайшем
автообновлении ответит заглушкой («Device limit reached»), и она, как при любом
обновлении, заменит серверы подписки. Восстановленные серверы при этом ещё
работали бы — лимит устройств панель проверяет только при выдаче подписки. Не
обходим: владелец панели решил, что устройств хватит, и клиент, который
держит старый список вопреки ответу панели, обходил бы её лимит. Вопрос перед
заменой говорит «HWID не переносится: панель увидит этот телефон», карточка
подписки — что именно ответила панель.

**Шифрование.** Пакет `cryptography` 2.9.0 (Apache-2.0, совместим с GPL-3.0),
только классы `Dart*` — чистый Dart, без нативного кода и без плагина, который
мог бы подменить реализацию.

- KDF — **Argon2id**, m = 64 МиБ, t = 3, p = 4, соль 16 байт — второй
  рекомендованный вариант RFC 9106 §4. Замер (Pentium G5400, AOT): 0,73–0,82 с;
  на телефоне ожидается 1,5–4 с, для редкого явного действия приемлемо.
  PBKDF2 отвергнут: в чистом Dart 600 тыс. итераций — 20–40 с на телефоне, а
  столько, сколько терпимо по времени, — слабо.
- AEAD — **ChaCha20-Poly1305** (RFC 8439), nonce 12 байт. AES-GCM в чистом
  Dart табличный (не постоянного времени) и вдвое медленнее. Случайного nonce
  достаточно: у каждого файла своя соль, значит свой ключ.
- Работа — в отдельном изоляте: секунда деривации на UI-изоляте — замерший
  экран.

**Формат файла** (имя по умолчанию `commy-ГГГГ-ММ-ДД.commybackup` — день
сохранения, пользователь может поменять; внутри файла вне шифртекста даты
нет):

```text
смещение  размер  поле
       0       8  "COMMYBAK"
       8       1  версия контейнера = 1
       9       1  KDF = 1 (Argon2id v1.3)
      10       1  AEAD = 1 (ChaCha20-Poly1305)
      11       1  флаги = 0
      12       4  память Argon2, КиБ (big-endian)
      16       4  проходы Argon2       (big-endian)
      20       1  потоки Argon2
      21       1  длина соли = 16
      22       1  длина nonce = 12
      23       1  резерв = 0
      24      16  соль
      40      12  nonce
      52       4  длина шифртекста n (big-endian)
      56       n  шифртекст (UTF-8 JSON, "format": "commy-backup", "schema": 1)
    56+n      16  тег Poly1305
 56+n+16       …  игнорируется
```

Весь 56-байтный заголовок — associated data: изменённый параметр ломает
аутентификацию так же, как изменённый байт шифртекста. Снаружи — только «это
копия Commy»: ни даты, ни версии, ни числа серверов. Длина в заголовке — из-за
того, как файл пишется: системный диалог может отдать существующий файл на
перезапись, `file_picker` открывает его `openOutputStream(uri)` в режиме `"w"`,
а часть провайдеров документов в этом режиме не усекает файл. Короткая копия
поверх длинной оставила бы старый хвост, тег читался бы из него — копия не
открывалась бы никогда. С длиной хвост просто игнорируется.

Читатель проверяет всё, что можно, **до** деривации: магию, версию и
алгоритмы (неизвестные → «сделано более новой версией»), длину, границы
параметров — не больше **удвоенных** текущих (m ≤ 128 МиБ, t ≤ 6, p ≤ 8):
будущей версии хватит места поднять параметры без нового контейнера, а
подложенный файл не заставит открытие стоить заметно дороже настоящего.
Неверный пароль и изменённый файл — один ответ: аутентифицированное
шифрование их не различает.

**Пароль.** Не короче 8 символов, дважды при выборе, как набран — без обрезки
пробелов и нормализации. Нигде не хранится и не логируется; клавиатуре
запрещено запоминать и подсказывать (`CommyTextField.isSecret`) — и когда
пароль показан открытым текстом. Утерян пароль — утеряна копия; лист выбора
пароля говорит это до того, как файл создан. Затирание ключа и открытого
текста в памяти — по возможности: Dart не умеет затирать строки, и
обещание здесь — R2 (ни байта на диск и в лог), а не «ничего в памяти».

**Куда уходит файл.** Только в системный диалог сохранения
(`FilePicker.saveFile`, на Android — Storage Access Framework «создать
документ»): байты пишутся прямо туда, куда указал пользователь, без нашей
копии рядом. Не share sheet — его первые цели мессенджеры и облака. Открытый
текст на диск не попадает никогда (R2). При восстановлении размер файла
проверяется до чтения (больше 32 МиБ — не наша копия), а копия, которую
выбор файла кладёт в кэш приложения, удаляется сразу после чтения.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| `pointycastle` | Его `BaseAEADCipher.process()` не вызывает `doFinal`: с ChaCha20-Poly1305 очевидный вызов дал нулевой тег на векторе RFC 8439 — аутентификация молча пропущена. Mutable API в духе BouncyCastle, Argon2 только синхронный |
| `javax.crypto` через канал | `PBKDF2WithHmacSHA256` только с API 26 (minSdk 24), Android-only, в VM не тестируется |
| Go `x/crypto` в `core/mobile` | Привязывает копию к ядру и каналу; на десктопе `core/cshared` ещё нет |
| Свой AEAD поверх `package:crypto` | Самодельная криптография — то, от чего отказались в ADR-0007 |
| Бэкап Android (`allowBackup`) | Секреты в облаке Google; нарушает R2 и «без облака» |

## Последствия

- **Вес APK (R11).** `cryptography` в AOT-снимке — около 172 КБ несжатого
  кода, в сжатом `libapp.so` меньше; рост APK — в коммите функции, по
  `scripts/check_apk_size.sh`.
- **Модель угроз** (docs/09) получила строку «тот, к кому попал файл копии»:
  офлайн-перебор пароля. Защита — Argon2id и минимальная длина; честно
  записано, что слабый пароль остаётся слабым.
- **Тесты-стражи:** векторы RFC 9106 и RFC 8439 (бамп библиотеки, изменивший
  примитив, упадёт здесь), закоммиченный файл формата v1 (изменение формата
  сломает открытие старых копий — упадёт здесь), круг «телефон A → файл →
  телефон B» через настоящие репозитории.
- **Не проверено:** время деривации на настоящем телефоне владельца —
  параметры в заголовке, поднять или опустить их можно без смены формата.
