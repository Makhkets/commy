# ADR-0019 · Восстановление домена подписки: подписанный манифест оператора, Commy Cloud — только курьер

**Статус:** принято · 2026-10-05, агентом по поручению владельца («добавь те
киллерфичи», «решения принимай сам»). Владелец ответил сам на три вопроса,
которые за ним: сервер разворачиваем на `31.76.100.71`, код Cloud — открыто в
монорепо, Pro пока бесплатно ([19-commy-cloud.md](../19-commy-cloud.md)).
**Контекст правил:** R1 (новое исключение **E-4**), R2, R3, R6;
[19-commy-cloud.md](../19-commy-cloud.md) §2 — постановка задачи;
[ADR-0008](0008-subscription-identity.md) — что такое «та же подписка»;
[ADR-0009](0009-device-identifier.md) — кому уходит HWID.

---

## Контекст

У оператора панели (Remnawave, Marzban) сотни и тысячи выданных ссылок вида
`https://sub.оператор.ru/sub/<токен>`. Домен блокируют (РКН, провайдер),
отбирают (регистратор) или он просто истекает — и у каждого клиента
подписка перестаёт обновляться. Сегодня ни один клиент (Happ, INCY, v2rayNG)
это не лечит: пользователь пишет в поддержку, получает новую ссылку,
переимпортирует. Для оператора это отток, для пользователя — вечер без сети.

Требования из 19-commy-cloud.md §2.2:

1. Ответу «твой новый домен — X» **нельзя верить на слово** — иначе это
   готовый угон подписки: кто подменил ответ, тот увёл всех клиентов на
   свои серверы.
2. Старый домен в момент переезда может быть мёртв — значит, о переезде
   нужно узнать **не у него**.
3. Commy Cloud не должен стать новой точкой доверия: взлом Cloud не должен
   давать власти над клиентами.
4. Аварийный тормоз: даже с украденным ключом оператора смена домена не
   происходит молча.
5. Базовый клиент не знает о Commy Cloud: **в приложении нет ни одного
   зашитого адреса Cloud**. Если Cloud исчезнет, обычные подписки этого не
   заметят.

## Решение

### Манифест

Оператор держит **ключ Ed25519** (RFC 8032). Приватная половина не покидает
его браузер или машину; Commy Cloud хранит только публичную. Ключом
подписывается **манифест** — маленький JSON:

```json
{
  "v": 1,
  "id": "axm",
  "seq": 3,
  "iat": 1791160000,
  "origin": "https://sub.makhkets.online",
  "mirrors": ["https://sub2.makhkets.site"],
  "rendezvous": ["https://commy.makhkets.ru/r/axm"],
  "key": "<32 байта публичного ключа, base64url без =>",
  "next_key": "<необязательно: следующий ключ>",
  "name": "AXM VPN"
}
```

| Поле | Смысл | Ограничения |
|---|---|---|
| `v` | версия формата | ровно `1` |
| `id` | проект оператора | 1–64 символа `[A-Za-z0-9_-]` |
| `seq` | номер выпуска | целое ≥ 1, строго растёт; меньший или равный уже принятому — не новость |
| `iat` | когда подписан | секунды Unix; показывается пользователю |
| `origin` | **основной адрес** подписки | `http(s)://хост[:порт]`, без пути, запроса, фрагмента и userinfo |
| `mirrors` | запасные адреса той же панели | до 8 origin-ов той же формы |
| `rendezvous` | где взять **свежий** манифест, если `origin` и зеркала молчат | до 4 полных `https`-URL |
| `key` | ключ, которым подписан этот манифест | 32 байта, base64url |
| `next_key` | объявленная ротация | то же |
| `name` | имя оператора для диалога | до 64 символов |

Передача — компактная строка, как JWS без заголовка:

```text
v1.<base64url(JSON)>.<base64url(подпись)>
```

Подпись — Ed25519 над **ASCII-байтами `v1.<base64url(JSON)>`** (префикс версии
подписан, подмена версии ломает подпись). Строка не длиннее 4096 байт.

Как манифест попадает к клиенту:

- **заголовок ответа подписки** `commy-manifest: <строка>` — оператор
  добавляет его сам: в Remnawave — «Subscription settings → custom response
  headers», в Caddy/nginx — одной директивой. Commy Cloud генерирует строку и
  подсказку, но в цепочке подписки не стоит;
- **точка встречи (rendezvous)** — `GET <url>` отдаёт ту же строку телом
  (`text/plain`). Её держит Commy Cloud (или кто угодно: формат открыт,
  сервер — в этом же репозитории, `cloud/`).

### Доверие — TOFU с закреплением ключа

Состояние восстановления хранится **на подписке** (`SubscriptionRecovery`):
закреплённый ключ, `id`, последний принятый `seq`, доверенные зеркала и точки
встречи, ожидающая решения смена адреса, отказанный `seq`, время последнего
визита на точку встречи, выключатель.

Правила (`RecoveryPolicy` в `commy_domain`, чистая функция, без сети):

1. **Подпись проверяется всегда.** Неверная, другой `id`, ключ не совпадает
   с закреплённым (и не равен объявленному `next_key`) — манифест молча
   игнорируется (в лог — причина без адресов, R3).
2. **Закрепление (TOFU)** — только по манифесту, пришедшему **с основного
   адреса** подписки при её добавлении или обновлении. С зеркала и с точки
   встречи ключ не закрепляется: туда клиент ходит, только когда ключ уже
   есть.
3. **`seq` не откатывается.** Меньший — отказ (защита от повтора старого
   подписанного манифеста), равный — нет новостей.
4. **Тихо** принимается только то, что пришло **с основного адреса** и не
   меняет его: новые зеркала, точки встречи, имя, ротация ключа. Основной
   адрес и так распоряжается подпиской целиком — он ничего не получает
   сверх того, что уже имел.
5. **Смена основного адреса — всегда вопрос пользователю**, откуда бы ни
   пришёл манифест: «Провайдер «AXM VPN» сменил адрес подписки:
   `sub.makhkets.ru` → `sub.makhkets.online`. Подпись провайдера проверена.
   Доверять?». Это аварийный тормоз из требования 4.
6. **Новые хосты из непервичного источника** (зеркала, присланные точкой
   встречи или зеркалом) — тоже вопрос, вместе со сменой адреса: с них
   клиент будет скачивать подписку, и украденный ключ не должен тихо
   добавлять адреса злоумышленника.
7. **Отказ запоминается** (`declinedSeq`): тот же выпуск больше не
   предлагается; следующий, с большим `seq`, — предлагается.
8. **Ключ теряется — восстановление невозможно.** Это честное следствие
   отсутствия третьей стороны; дэшборд Cloud говорит об этом при создании
   ключа.

Принятая смена адреса переписывает в URL подписки **схему, хост и порт**;
путь и запрос (токен) остаются. Подписка та же (тот же `id`, ADR-0008), её
серверы и выбор не трогаются.

### Когда клиент ходит куда-то кроме основного адреса — исключение E-4

| Куда | Когда | Что уходит |
|---|---|---|
| **Зеркала** (`mirrors`) | основной адрес не ответил подпиской (сеть, TLS, 5xx, 4xx, не разобралось) | тот же запрос, что основному: путь с токеном, `User-Agent`, HWID-заголовки (ADR-0009). Зеркало — та же панель оператора под подписью его ключа, а панели с лимитом устройств без `x-hwid` отвечают заглушкой |
| **Точки встречи** (`rendezvous`) | (а) основной адрес и зеркала не ответили — не чаще раза в 15 минут; (б) обычное обновление прошло, а с прошлого визита больше 24 часов — чтобы узнать о переезде, когда старый домен **отобран** и отвечает чужим содержимым | голый `GET` без идентификаторов: `User-Agent: Commy/<версия>`, без HWID, без cookies, без токена подписки. Видят IP и `id` проекта |

Условия прозрачности — те же, что у E-1…E-3 (docs/09): адреса видны в
настройках («Тишина в сети») и в меню подписки до первого запроса;
выключатель «Восстановление адреса» в меню подписки выключает **всё** из
таблицы для этой подписки (манифест в заголовке при этом по-прежнему
читается — это не сеть); подписка без заголовка `commy-manifest` не
порождает ни одного такого запроса — ветка кода не исполняется.

### Что Commy Cloud видит и чего не видит

| Видит | Не видит |
|---|---|
| e-mail оператора, публичный ключ, опубликованные манифесты (адреса панели и зеркал) | приватный ключ оператора |
| IP клиента при визите на точку встречи, `id` проекта, версию Commy | токены подписок, HWID, список серверов, креды узлов |
| счётчики визитов по дням (уникальность — по хешу IP с суточной солью, IP не хранится) | трафик пользователей |

Cloud не может подделать манифест (нет приватного ключа) и не может увести
клиентов: смена адреса всё равно спрашивает пользователя, и подпись
проверяется на устройстве.

## Альтернативы

- **Доверять ответу Cloud без подписи** (`GET api/new-domain`). Просто, но
  тогда взлом Cloud — это угон всех клиентов всех операторов. Отвергнуто
  требованием 3.
- **Ключ на сервере Cloud** («подпишем за вас»). Удобнее оператору, но Cloud
  становится доверенной стороной. Отвергнуто тем же требованием. Для тех, кто
  не хочет возиться с браузером, есть CLI (`commy-cloud sign`), который
  работает офлайн.
- **Подписывать каждый ответ подписки (онлайн-ключ у панели).** Защитило бы и
  от отобранного домена, отдающего чужой список серверов. Но ключ тогда живёт
  на сервере панели, и протокол требует от оператора встроиться в саму
  панель — для Remnawave это недоступно. Отложено; v1 защищает **смену
  адреса**, а не тело подписки. Отобранный домен лечится визитом на точку
  встречи раз в сутки (правило б) и вопросом пользователю.
- **Зашитый адрес Commy Cloud в приложении.** Ломает требование 5 и делает
  Cloud точкой отказа. Отвергнуто: точки встречи приходят только из
  подписанного манифеста, оператор может держать свою.
- **DNS TXT как канал манифеста.** Блокировка домена обычно заодно ломает и
  его DNS; к тому же DNS-запрос на Android идёт мимо туннеля — ещё один вид
  трафика для E-4. Отвергнуто.

## Последствия

- **Плюс:** первая в классе (Happ, INCY, Hiddify, v2rayNG) защита подписки от
  блокировки домена без переустановки и новых ссылок; оператор ничего не
  встраивает в панель — один заголовок.
- **Плюс:** Commy Cloud заменим: протокол открыт, сервер — в репозитории
  (`cloud/`), оператор может поднять точку встречи сам.
- **Минус:** четвёртое исключение из R1 (E-4) — пусть узкое и выключаемое.
  Записано в docs/09 одновременно с кодом, как требует 19-commy-cloud.md §2.4.
- **Минус:** миграция БД v1 → v2: колонка `recovery_json` у подписок
  (состояние восстановления не секрет — в нём нет токенов, только хосты,
  которые и так лежат в `redacted_url`).
- **Минус:** потерянный ключ оператора — потерянная возможность переезда для
  его клиентов. Дэшборд требует сохранить ключ до публикации первого манифеста.
- Тело подписки в v1 не подписывается (см. «Альтернативы»).
