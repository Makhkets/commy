# 05 · Экраны и сценарии

> **Про визуал.** Этот документ описывает **структуру**: какие экраны есть, какие у
> них состояния, что происходит по шагам. Внешний вид определяется отдельно и сейчас
> перерабатывается — см. [04-design-system.md](04-design-system.md). Структура
> переживает смену визуального языка, поэтому её фиксируем уже сейчас.

---

## Карта приложения

```
Главная            планета подключения + подписки + узлы     ← единственный корневой
  ├ ⚙ слева   →  Настройки
  │                ├ Маршрутизация   режим, правила, приложения, DNS
  │                ├ Диагностика     логи, соединения, конфиг, статистика
  │                └ Внешний вид     тема, язык, размер шрифта
  └ ＋ справа →  Импорт              вставка, подписка, QR, файл
```

**На мобайле нижнего меню нет.** У Commy один основной экран: подписки, их узлы и
вручную добавленные группы живут прямо под кнопкой подключения — там же, где
принимается решение «жать или не жать». Отдельная вкладка «Серверы» дублировала бы
главную, а маршрутизацию и диагностику открывают реже раза в неделю. Освободившаяся
высота уходит в список.

| Ширина | Навигация |
|---|---|
| < 600 dp | Один корневой экран, вход в разделы из шапки, модальные bottom sheet |
| 600–1000 dp | `NavigationRail`, детали в правой панели |
| > 1000 dp | Боковое меню, двухпанельный layout, обычные диалоги |

Разделы возвращаются в постоянную навигацию только там, где для неё есть место.
Дублировать мобильную структуру на десктопе, как и наоборот, — ошибка.

## Сценарий 1 · Первый запуск

**Цель: от установки до зелёного статуса меньше чем за 60 секунд.**
Это метрика успеха из [00-vision.md](00-vision.md#как-меряем-успех), и весь экран
проектируется под неё.

```
Запуск
  │
  ▼
Пустое состояние Главной
  «Добавьте свой сервер»
  ├─ [Вставить ссылку]      ← если в буфере уже есть ссылка,
  │                            кнопка подсвечена и показывает превью
  ├─ [Подписка по URL]
  ├─ [Сканировать QR]
  └─ [Открыть файл]
  │
  ▼
Импорт  ──► ошибка? ──► показать причину + что делать. Экран не закрывается,
  │                     введённое не теряется
  ▼
Успех: «Импортировано 24 узла» (+ «3 пропущено» → ссылка на список причин)
  │
  ▼
Главная с выбранным узлом, кнопка активна
  │
  ▼
Нажатие → системный диалог VPN
  ├─ разрешено → starting → connected → checking → готово
  └─ отклонено → понятная ошибка + [Разрешить] ещё раз, без тупика
```

Онбординга с каруселью нет. Пустое состояние **само по себе** объясняет, что делать.

**Проверка буфера обмена** — только при открытии экрана импорта, не в фоне, и с
показом того, что нашли, до вставки.

## Сценарий 2 · Подключение

Шесть состояний, каждое обязано быть отличимым и понятным:

| Состояние | Что видит пользователь | Что можно нажать |
|---|---|---|
| `idle` | «Подключить», выбранный узел | Подключить, сменить узел |
| `starting` | «Подключение…», индикатор | Отмена |
| `connected` | «Подключено», таймер, скорость ↑↓ | Отключить, сменить узел |
| `checking` | «Проверка доступа…» | Отключить |
| `stopping` | «Отключение…» | — |
| `error` | Причина + **действие** | Повторить, Логи, Сменить узел |

**Почему `checking` отдельно.** Поднятый туннель не означает работающий интернет:
сервер мог умереть, квота кончиться, провайдер заблокировать. Если показать
«Подключено» и молчать, пользователь решит, что виновато приложение. Поэтому после
подключения идёт быстрая проверка, и её результат виден.

**Смена узла на лету.** Не отключаемся и не подключаемся заново — это разрыв всех
соединений. Меняем исходящий в работающем ядре.

## Сценарий 3 · Подписка

```
Узлы → [+] → Подписка по URL
  │
  ▼
Ввод URL, имя (необязательно), интервал автообновления
  │
  ▼
Загрузка  ──► недоступна ──► «Сервер не отвечает» + [Повторить]
  │                          Ошибка объясняет, что дело в сервере, а не в ссылке
  ▼
Разбор ответа
  ├─ узлы                    → сохранить
  ├─ subscription-userinfo   → показать квоту и срок
  └─ битые записи            → в список с причинами
  │
  ▼
Карточка профиля:
   имя · 24 узла · полоса квоты · «осталось 18 дней» · «обновлено 2 ч назад»
```

**Автообновление** уважает интервал сервера (`profile-update-interval`), если он
задан. Обновление идёт **мимо туннеля** по умолчанию — иначе первое обновление
после переустановки невозможно.

**Квота близка к концу или срок истекает** — карточка меняет тон и показывает это
до того, как всё сломается, а не после.

## Сценарий 4 · Выбор узла

Список живёт на Главной, прямо под кнопкой подключения — отдельного экрана нет.
Подписки идут **одна под другой**, каждая своей сворачиваемой группой.

```
Главная ↓ прокрутка
 ┌───────────────────────────────────────────────────┐
 │▒🛡 MAKHKETS VPN                     ⟳    ⏱    ⋯ ▒│  ← обновить · пинг · меню
 │▒   2 ч назад · авто 1 ч                          ▒│
 │▒   ▰▰▰▰▰▰▰▰▰▰▰▱▱▱▱▱▱▱▱▱▱▱                       ▒│     шапка подписки
 │▒   1,12 ТБ из 2 ТБ              осталось 18 дней ▒│     на bg/overlay
 │▒   id: Makhkets · связь в телеграм @tmaac        ▒│
 │▒─────────────────────────────────────────────────▒│
 │▒       ✈ Поддержка              🌐 Сайт          ▒│  ← ссылки провайдера
 ├───────────────────────────────────────────────────┤
 │ ▎🇳🇱 Amsterdam 03   VLESS · Reality · TCP   48 мс │  ← её узлы, bg/surface
 │   🇪🇺 Авто-Выбор     VLESS · Reality · TCP   41 мс │     активный: полоса слева
 │   🇵🇱 Poland 10gb/s  VLESS · Reality · TCP   62 мс │
 └───────────────────────────────────────────────────┘
 ┌───────────────────────────────────────────────────┐
 │▒🛡 Backup Panel                      ⟳    ⏱    ⋯ ▒│
 │   …                                               │
 └───────────────────────────────────────────────────┘
```

**Подписка и её узлы — одна карточка.** Шапка стоит на `bg/overlay`, узлы на
`bg/surface` — ступень фона делает границу группы очевидной без единой рамки.
Отдельными карточками они читались как несвязанные блоки, и было непонятно, какой
сервер к какой подписке относится. Воздух есть только **между** подписками.

- **Никакого «текущего провайдера».** Все подписки равноправны и просто идут списком;
  выделять одну — значит врать про модель, где узел можно взять из любой.
- **Три действия в шапке подписки, и ровно эти три:** обновить подписку, замерить
  пинг всех её узлов, меню «…». Первые два нажимают часто, поэтому они снаружи;
  всё редкое (свернуть, изменить, скопировать ссылку, интервал, удалить) — в меню.
- **Ссылки провайдера — отдельной панелью в футере карточки**, за разделителем.
  Так они не разъезжаются, когда у подписки длинное описание, и всегда лежат на
  одном месте.
- **Описание провайдера** (`id`, телеграм) показывается как есть, одной строкой:
  это то, что админ написал своим пользователям, и переписывать его не наше дело.
- **Активный узел помечается полосой слева**, а не галочкой справа: полоса не отнимает
  места в строке и ловится боковым зрением при прокрутке.
- **Порядок подписок сохраняется** тем, в каком они добавлены; узлы внутри — в том
  порядке, в каком их отдала панель.
- **Флаг — вектор**, а не эмодзи: одинаково выглядит на всех пяти платформах.
- **Задержка** — цветом и числом одновременно, никогда только цветом.
- **Замерить все** идёт пачками, не блокирует UI, показывает прогресс, отменяется.
- **Auto** — не узел, а группа: выбирает лучший и перепроверяет по интервалу.
- **timeout** не прячет узел: сервер мог быть временно недоступен. Скрытие
  нерабочих — отдельный переключатель.

## Сценарий 5 · Маршрутизация

Экран построен от простого к сложному. 90% пользователей не пойдут дальше первой
строки.

```
Режим:  ( Глобально )  [ Правила ]  ( Прямо )     ← сегментированный переключатель
─────────────────────────────────────────
Правила                                  [+]
  geosite:ru        → Прямо               ⠿     ← перетаскивание = приоритет
  geoip:private     → Прямо               ⠿
  geosite:ads       → Блок                ⠿
  Остальное         → Прокси                    ← финальное, не удаляется
─────────────────────────────────────────
Приложения                          Только выбранные · 7  →
Наборы правил                       geoip 2 МБ · geosite 8 МБ  →
DNS                                                          →
```

- Порядок = приоритет. Перетаскивание — самый понятный способ это выразить.
- Правило «Остальное» всегда последнее и неудаляемое: у маршрутизации обязан быть
  финальный исход.
- **Наборы правил не скачиваются сами.** Экран показывает размер и источник, и
  ждёт нажатия — это исключение E-2 из [09-security-privacy.md](09-security-privacy.md#тишина-в-сети--правило-r1-и-его-исключения).

**Приложения** (там, где ОС позволяет): выбор режима «только выбранные» или «все
кроме выбранных» — взаимоисключающие, один переключатель, а не два списка.
Собственное приложение всегда исключено и показано серым с пояснением.

## Сценарий 6 · Что-то не работает

Самый важный и самый недооценённый сценарий. Пользователь приходит сюда злым.

```
Диагностика
 ├─ Логи            уровень, поиск, [копировать] [экспорт]
 ├─ Соединения      хост · правило · узел · скорость · длительность
 ├─ Конфиг          сгенерированный JSON, только чтение
 └─ Статистика      график 60 с · трафик по дням
```

- **Логи** — моноширинный, цвет по уровню, автопрокрутка с паузой при ручном
  скролле.
- **Копирование и экспорт** проходят через редакцию секретов (правило R3). Экспорт
  сырого лога возможен, но с явным подтверждением и текстом о том, что в нём окажется.
- **Соединения** отвечают на вопрос «почему этот сайт идёт мимо прокси» — видно,
  какое правило сработало.
- **Конфиг** отвечает на «что вообще получилось» — прозрачность из принципа 3.

Каждая ошибка на любом экране имеет ссылку сюда. Ошибка без пути к диагностике —
недоделанная ошибка.

## Обязательные состояния каждого экрана

Экран не готов, пока нет всех четырёх. Это часть Definition of Done.

| Состояние | Требование |
|---|---|
| **Загрузка** | Скелетон, а не спиннер по центру, если известна структура |
| **Пусто** | Иконка, объяснение и **действие**. «Нет данных» — это не пустое состояние |
| **Ошибка** | Причина человеческим языком + действие + путь к логам |
| **Успех** | Собственно контент |

## Десктоп: что добавляется

| Возможность | Зачем |
|---|---|
| Трей с текущим статусом и быстрой сменой узла | Основной способ взаимодействия — окно открывают редко |
| Закрытие окна сворачивает в трей | Закрытие окна не должно рвать туннель |
| Глобальные горячие клавиши | Подключить/отключить не открывая окно |
| Логи в отдельном окне | Смотреть логи и менять настройки одновременно |
| Запуск свёрнутым при старте системы | |

Десктоп — **не растянутый мобильный экран**. Двухпанельная компоновка: список
слева, детали справа. Плотность выше, отступы меньше.

## Доступность

- Тап-таргеты ≥ 48 dp везде.
- Цвет никогда не единственный носитель смысла: статус = цвет + иконка + текст.
- Экран не разваливается при системном шрифте 200%.
- `MediaQuery.disableAnimations` уважается — пульсация и вращение заменяются
  мгновенной сменой.
- Все интерактивные элементы имеют семантические метки для скринридера.
- Полная работа с клавиатуры на десктопе, видимый фокус.
