# 01 · Стек

Каждая строчка здесь — решение, за которое кто-то будет расплачиваться через год.
Поэтому у каждой есть обоснование. Крупные решения вынесены в [adr/](adr/).

## Обзор

```
┌──────────────────────────────────────────────────────────┐
│  Flutter · Dart          UI, состояние, бизнес-логика     │  1 кодовая база
├──────────────────────────────────────────────────────────┤
│  Kotlin │ Swift │ C++ │ C   платформенный туннель         │  5 тонких слоёв
├──────────────────────────────────────────────────────────┤
│  Go · sing-box (libbox)     сеть, протоколы, TUN, DNS     │  1 ядро
└──────────────────────────────────────────────────────────┘
```

Принцип: **толстое ядро, тонкая платформа, единый UI.** Всё, что можно унести в
Go или Dart, туда и уносится. Нативный код — только то, что физически невозможно
написать иначе: системный VPN API каждой ОС.

## Сетевое ядро

### sing-box · Go · GPL-3.0 → [ADR-0002](adr/0002-singbox-core.md)

Почему именно оно, а не Xray-core:

- **`experimental/libbox`** — пакет, спроектированный ровно под нашу задачу:
  `PlatformInterface` (открыть TUN, защитить сокет, найти владельца соединения,
  следить за сменой сети), `CommandServer`/`CommandClient` для IPC из UI-процесса.
  Это готовый мост к `VpnService` и `NEPacketTunnelProvider`. Написать его самому —
  два-три месяца.
- **Встроенный TUN-стек** (gVisor и системный). Xray потребовал бы отдельный
  `hev-socks5-tunnel` и свою обвязку на каждой платформе.
- **Все протоколы из коробки**: VLESS/Reality, VMess, Trojan, Shadowsocks,
  Hysteria2, TUIC, WireGuard, ShadowTLS, SSH. У Xray нет Hysteria2 и TUIC.
- **Clash API** — готовый HTTP/WebSocket-интерфейс для статистики, логов, списка
  прокси и замера задержки. Мы переиспользуем его как транспорт UI↔ядро на
  десктопе вместо изобретения своего протокола.
- Прецедент: на sing-box построены Hiddify и Karing — оба покрывают все пять
  платформ. Дорога протоптана.

Цена решения: **GPL-3.0 заражает весь проект.** Для опенсорса это не проблема, но
есть нюанс с App Store — разобран в [11-licensing.md](11-licensing.md).

Версия ядра **пинится точно** и обновляется отдельным PR (правило R8 в CLAUDE.md).

## UI

### Flutter (stable) · Dart → [ADR-0001](adr/0001-flutter-ui.md)

Единственный фреймворк, который даёт одну кодовую базу UI на все пять целей и при
этом собирается в нативный бинарник без JVM и без Electron. Compose Multiplatform
тянет JVM на десктоп (80–150 МБ и прожорливость по RAM для утилиты в трее — это
неприемлемо), Tauri не имеет протоптанного пути к iOS Network Extension.

Версия пинится через **FVM** (`.fvmrc`). Разные версии Flutter у разработчиков —
источник плавающих golden-тестов.

| Зависимость | Зачем | Заметки |
|---|---|---|
| **riverpod** 3 + `riverpod_generator` | Состояние | Кодоген, компайл-тайм граф зависимостей, тестируемость через `ProviderContainer` |
| **go_router** | Навигация | Один граф маршрутов для мобайла и десктопа, deep links «из коробки» |
| **freezed** + `json_serializable` | Модели | Иммутабельность, `copyWith`, исчерпывающие `when` для состояний соединения |
| **drift** | БД (SQLite) | Работает на всех 5 платформах, типизированные запросы, миграции |
| **sqlcipher_flutter_libs** | Шифрование БД | Правило R2. Ключ — в secure storage |
| **flutter_secure_storage** | Ключи и токены | Keychain / Keystore / DPAPI / libsecret |
| **dio** | HTTP | Нужны интерцепторы, отмена, и главное — умение ходить **мимо** активного туннеля при обновлении подписки |
| **slang** | i18n | Типобезопасно: опечатка в ключе — ошибка компиляции, а не пустая строка в проде |
| **ffigen** | Биндинги к `core/` | Генерация Dart FFI из C-заголовка |
| **lucide_icons_flutter** | Иконки | ISC, единая сетка 24px, штрих 1.5–2 — совпадает с нашей дизайн-системой |
| **window_manager**, **tray_manager**, **launch_at_startup** | Десктоп | Окно, трей, автозапуск |
| **mobile_scanner** | QR | Импорт конфига камерой |
| **app_links** | Deep links | Схемы `commy://`, `sing-box://`, импорт из `happ://` |
| **very_good_analysis** | Линт | Строгий пресет, предупреждения = ошибки |
| **melos** | Монорепо | Один `bootstrap`, общие скрипты, версионирование пакетов |

**Сознательно НЕ берём:** любые SDK аналитики, `firebase_*`, рекламные сети,
пакеты автообновления, ходящие в свои CDN. Правило R1.

## Нативный слой

Пишем ровно столько, сколько требует ОС. Логика — в Go, не здесь.

| Платформа | Язык | Что делает | API |
|---|---|---|---|
| Android | Kotlin | Foreground `VpnService`, реализация `PlatformInterface`, per-app правила через `addAllowedApplication` | `VpnService`, `ConnectivityManager` |
| iOS / macOS | Swift | `NEPacketTunnelProvider` в расширении, IPC через unix-сокет в App Group | `NetworkExtension` |
| Windows | C++ | Служба с правами администратора, поднимает Wintun-адаптер и хостит ядро | Wintun, SCM, named pipe |
| macOS (вне стора) | Swift | Привилегированный хелпер, `utun` | `SMAppService` |
| Linux | C / Go | Хелпер с `CAP_NET_ADMIN`, авторизация через polkit | `/dev/net/tun`, systemd, D-Bus |

Детали — в [03-platform-tunnel.md](03-platform-tunnel.md).

## Что осознанно отложено

| Технология | Почему не сейчас |
|---|---|
| Xray-core вторым ядром | Абстракция `CoreEngine` стоит времени на старте и всё равно не снимает GPL. Вернёмся, если появится протокол, которого нет в sing-box |
| Rust вместо Go в ядре | Ядро мы не пишем — мы его встраиваем. Язык ядра выбран за нас |
| Собственный TUN-стек | Есть в sing-box, писать свой — чистый убыток |
| WebAssembly / браузерная версия | Браузер не умеет TUN. Максимум — конфигуратор, это не продукт |
| Собственный протокол | Мир не нуждается ещё в одном протоколе, а пользователи — в несовместимости |
